# recovery_close 상위 이익 5건 원본 검토

PR #80의 `report-244.json`을 검토한 후, 계좌 비교에 앞서 큰 이익의 저장 가격 근거를 확인하는 단계입니다. 이 도구는 계좌 재현이나 운영 조건 변경을 하지 않습니다. PR #80 코드 위에 추가했으며 원래 연구 코드와 지문은 바꾸지 않습니다.

## 고정 대상

`selection.json`에 결과를 보고 선택한 상위 이익 5건을 고정했습니다. 대표 표본·블라인드·전략 유효성 검증이 아닙니다.

| 신호일 | 종목 | 독립 관찰 수익률 |
|---|---|---:|
| 2026-07-09 | SK이터닉스 | +45.5909% |
| 2026-07-07 | SK이터닉스 | +45.5181% |
| 2026-06-08 | 제주반도체 | +43.2734% |
| 2026-01-14 | 삼표시멘트 | +36.5115% |
| 2026-04-03 | LS머트리얼즈 | +28.9285% |

SK이터닉스 두 신호를 합치거나 지우지 않습니다. 5건은 4종목이며 동일 상승 중복을 살펴볼 근거로 남깁니다.

## 확인 범위

- 첨부 보고서 원본 바이트 SHA256, 원래 연구 코드 LF 해시, 전략 지문, 후보·기준 로그 해시를 비교합니다.
- v2 전체 데이터셋 `verify`와 봉 해시 묶음이 실행 보고서와 같아야 합니다. 추가 수집하지 않습니다.
- 신호일까지의 전체 봉으로 조건을 다시 계산합니다. 미래 가격을 신호 입력에 넣지 않습니다.
- 같은 TradeSimulator 재실행과 별도 구현한 고정 지정가 체결 경로 대조를 구분합니다. 별도 구현도 동일한 일봉·규칙 가정을 사용하며 독립 전략 구현이 아닙니다.
- 신호 이후 거래일의 누락·무효 봉을 건너뛰지 않습니다. 대상의 청산까지 일봉을 따로 보관합니다.
- 매수·청산 가격이 당일 고저 범위 안인지 확인합니다. 모형 일치와 실제 체결 가능성은 다릅니다. 범위 밖 가격을 고치지 않습니다.
- 기존 Yahoo 원응답의 해시를 확인하고 해당 날짜 OHLCV·수정종가·기업행사 필드만 추출합니다. 저장 봉과 다른 필드·원응답 날짜 누락·중복을 남깁니다.
- 종가 30% 초과 변동, 기존 종가 보정 흔적과 품질 정보도 보관합니다. 점프가 없다는 이유로 수정주가 기준이 맞다고 확정하지 않습니다.

출력 JSON에는 신호일까지의 가격과 청산까지의 가격이 구분되어 있습니다. 차트를 직접 그리기 위한 근거이며 이 단계에서 사람이 차트를 검토했다는 뜻은 아닙니다.

기본 출력:

```text

```

출력은 Git·원본 폴더 밖 새 파일에만 씁니다. 이미 있으면 덮어쓰지 않고 거절합니다. 필요하면 존재하는 별도 폴더의 새 파일을 `--output=...`으로 지정하세요. 기존 report-244.json을 편집하거나 포맷 변환하지 마세요.

- 종료 0: 저장 모형 대조 통과. 원응답 차이·가격 범위 경고·주가 수정 기준은 별도로 검토해야 합니다.
- 종료 2: 모형 불일치가 있으며 출력 JSON에 차이가 기록됐습니다. 계좌 비교로 진행하지 마세요.
- 종료 1: 입력/해시/파일/실행 오류. 원본을 고치거나 재수집하지 말고 오류를 공유하세요.

**결과 JSON 하나와 출력 요약·종료 코드를 공유하세요.** 인증키·운영 계좌·전체 원본 ZIP은 필요 없습니다. 이 JSON에는 선택 사례의 로컬 저장 가격과 Yahoo 응답 일부가 포함됩니다. 원본 응답 전체의 바이트를 첨부한 것은 아닙니다.

## 현재 검증과 다음 단계

개발 환경에서는 합성 체결 경로, 일봉 범위, 변조 탐지, 미래봉 차단, 원응답 해시·경로 검사를 검증했습니다. 실제 상위 5건의 원본은 사용자 PC에 있으므로 추출과 원본 대조 결과는 아직 없습니다.

실제 자료 확인 후에만 `recovery_close` 하나를 제외하는 연구 대안을 고정합니다. 초기 자금·보유 한도·비용·손절·목표·공통 위험은 유지하고 기준 계좌 재현 일치부터 확인해야 합니다. 결과가 좋은 임계값을 탐색하거나 운영에 자동 반영하지 않습니다.
