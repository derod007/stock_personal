# 과거 데이터 변경 진단

머지 후 기존 프로젝트를 갱신하면 다음 historical_revision 발생부터 상세 보고서를 보관합니다. 스케줄러 명령이나 계좌 ID 변경은 필요 없습니다. 기존 중단/리셋 정책과 전략 해시는 유지합니다.

실행·추천 진단 → 과거 데이터 변경 진단에서 최신 중단 보고서를 조회합니다. 봉 날짜/종목/변경 필드/이전 값/새 값/차이/변화율/발견 시각/입력 출처를 표시합니다. 전체 JSON 링크로 화면의 200봉 제한 없이 확인할 수 있습니다.

수집 원본은 기존 방식으로 보관하고, 전체 변경 보고서는 inputs/<sha256>.data에 내용 해시로 저장합니다. data_revision 이벤트에 보고서 해시를 연결합니다. 조회 시 해시를 검증합니다. 과거 추천·거래·가격 이력은 수정하지 않습니다. 숫자 표현(정수/실수), 필드 존재 여부, 키 순서 차이도 중단을 자동 해제하지 않습니다. 변화율은 이전 값의 절댓값 대비이며 이전 값 0이면 미표시합니다.

보고서는 보존 이력과 수집 후 병합 이력을 마지막 고정 추천 시점까지 비교합니다. 수집 기간 이동으로 오래된 봉이 빠지는 경우는 기존 보존 이력을 유지하므로 삭제로 오인하지 않습니다. 최초 불일치 종목뿐 아니라 모든 종목의 변경을 수집합니다. 이전 출처는 마지막 보존 추천의 출처이며 해당 봉 최초 수집 출처를 뜻하지 않습니다.

영향 범위는 변경일 이후 같은 종목의 추천 키와 주문/체결/청산 이벤트를 보수적으로 연결한 것입니다. 실제 추천·손익 변경을 재계산한 결과가 아닙니다. 공급자 정정/기업행동/수집 오류 중 원인은 이 보고서만으로 확정하지 않습니다.

이미 중단됐거나 리셋해 백업에만 남은 계좌는 자동 복구·해제·재작성하지 않습니다. 과거 data_revision에 보고서 해시가 없으면 '상세 진단 도입 이전 기록'으로 표시합니다. 새 진단을 얻으려고 운영 계좌의 halted 플래그를 수동 해제하지 마세요.

검증은 네트워크 없는 합성 데이터로 실제 계좌 CLI를 실행해 rolling window 무변경, 거래량 정정 감지, 이전 이벤트/고정 추천/가격 보존, 보고서 해시, 중단 후 재실행 거부를 확인합니다.
