# 유형1 마감 고정 후보 및 독립 관찰

`type1_scan.php`의 **마감 고정 후보 · 신규/관찰 중 · 결과 보기**에서 `type1_tracking.php`로 이동한다. 실시간 스캔은 기존대로 유지하며 판단 종가 대비 조회 가격 변화율도 표시한다. 고정 화면 조회는 네트워크 수집이나 기록 변경을 하지 않는다.

## 적용 후 동작

한국 `paper_daily.py`의 독립 후속 단계에서 `php bin/type1_track.php`를 한 번 호출한다. 기존 추천 0건이나 계좌 처리 실패 때도 시도하며, 이 단계 실패가 기존 계좌 종료 코드를 바꾸지 않는다. Windows 예약 시각·명령 및 매매 전략·계좌 파일은 변경하지 않는다. 이 PR을 병합하고 로컬에 적용하면 기존 한국 daily의 다음 실행부터 저장된다. 설치 서버에서 실제 외부 수집 성공 여부는 최초 실행 로그의 `type1_tracking`으로 확인해야 한다.

기본 위치: `PAPER_STATE_DIR/type1-observations/` (환경변수 없으면 저장소 부모의 `stock-personal-paper/type1-observations`).
- `snapshot-YYYY-MM-DD.json`: 최초 마감 수집의 순위, 실제 사용 가격, 달력, 수집시각. 덮어쓰지 않는다.
- `latest.json`: 누적 판정과 개별 모의 경로. 잠금 및 임시 파일 교체로 기록한다.
- 스냅샷 저장 후 상태 교체 전 중단되면 다음 실행이 미반영 스냅샷부터 복구한다.
- 같은 날 재실행은 기존 기록을 유지한다. 최초 수집의 평가 불가를 나중에 새 후보로 고치지 않는다.

## 규칙과 표시

1. 한국 시각 16시 이전·주말에는 수집하지 않는다. KOSPI/KOSDAQ 네이버 일봉 날짜가 일치하고 최신일이 오늘이어야 진행한다. 이는 거래소 공식 휴장 달력 검증은 아니다. 두 지수에 공통으로 누락된 거래일은 자동 발견할 수 없다.
2. 마감 후 TOP100을 새로 조회한다. 원래 순위 제공 API 응답에는 거래일이 없으므로 **당일 최종 TOP100 여부 미확정**으로 기록·표시한다. 장 종료 뒤 조회했다는 사실만으로 검증 완료로 만들지 않는다.
3. TOP100의 각 종목은 분류 결과와 무관하게 최초 관찰 T~T+20 구간을 소비한다. 중간 TOP100 이탈도 구간을 끝내지 않는다. T+21 이후 재등장하면 다음 구간이다. 서비스 시작 전 최초 등장 여부는 미확정이다. 수집이 빠진 날의 후보도 복원하지 않는다.
4. 구간 첫날이 유형1이고 **당일 완료봉**으로 판정됐을 때만 독립 모의 경로를 생성한다. 기존 고정 중심·60봉·자료 오류 거부를 유지한다. 6자리 영문 혼합 종목코드도 분류기에 입력 가능하게 했다. 상위 순위 수집기의 원래 시장 범위·종목 추출 방식은 바꾸지 않는다.
5. 다음 **시장 거래일 시가**, 손절5%, 목표15%, T+20 종가. 수수료·슬리피지 합계 매수/매도 각각0.15%. 같은 봉 손절+목표는 손절 우선, 실제 장중 순서는 미확정. 손절 아래 시가 공백은 그 시가 적용. 계좌 한도나 수량은 적용하지 않으며 계좌 수익률로 합산하지 않는다.
6. 종목이 TOP100에서 빠져도 미종료 경로는 계속 조회한다. 다음 거래일 봉이 없으면 그다음 봉으로 매수를 옮기지 않고 `가격 미확정`으로 남긴다. 이후 해당 봉이 확보되면 재평가할 수 있지만 이미 고정한 유효 봉과 종료 결과는 수정하지 않는다.
7. 가격은 마감 수집 시 관찰된다. 장중 알림·실시간 손절·실제 체결 보장은 없다. 모형 매수가와 손절/목표 가격은 다음 시가를 확인한 뒤 표시한다. 대기 시에는 가격을 예측해서 채우지 않는다.

## 검증

- PHP 합성 검사: 미래봉 제외, 영문 코드, 중복, 20/21세션 경계, 비유형/평가불가도 구간 소비, TOP100 이탈 후 종료, 손절·목표 동시 접촉, 시가 갭, 수수료, 누락 봉 보류/회복, 가격 수정 방지, 재실행 및 중간 중단 복구, 표시 escaping, 달력 불일치.
- Python daily 검사: 기존 흐름 유지 및 독립 추적 실패의 계좌 결과 비전파.
- 최근 244거래일(2025-10-10~2026-10-08)을 하루씩 재생. 기존 1,010건 중 **1,009건의 진입가격·청산일·청산가격·청산사유·비용 반영 손익률 일치**. 나머지 `009830.KS / 2026-05-22`는 기존 화면의 최근60봉 OHLC 모순 거부로 평가 불가. 과거 Python 연구는 잘못된 봉을 먼저 제외한 뒤 60봉을 선택하므로 자료 처리 차이가 있다. 이 1건을 일치로 주장하지 않는다.
- 새 모형은 미래창이 짧다고 현재 후보를 버리지 않으므로 마지막20세션의 **104건**을 추가 관찰한다. 총1,113건 중1,090종료·21관찰중·2다음시가대기. 이 숫자는 기능 재생 대조이며 새로운 수익성 검증이 아니다.
- 과거 저장 가격을 잘라서 재생했으며 당시 실제 공급자가 제공했을 시점/수정 전 가격을 입증하지 않는다. Yahoo/Naver 혼합 공급 클라이언트의 수정주가 검증을 추가한 작업이 아니다.

## 오프라인 재생

원본 계좌를 실행하지 않는다. 출력은 반드시 신규 경로를 지정한다.

```sh
php tests/type1_tracking.php
php tests/type1_scan.php
python -m unittest tests.test_paper_daily
python docs/research/type1_tracking_replay.py --candidates docs/historical-top100-20251008-20261008/candidates.json --bars-zip /path/to/kr-dated-amount-top100-20251008-20261008-v2.zip --output /tmp/type1-replay-new.json
```

완성 스냅샷을 CLI로 검증할 경우 `php bin/type1_track.php --snapshot=/path/snapshot.json --state-dir=/path/isolated-tracker`로 별도 폴더를 명시해야 한다. 운영 장부를 삭제하거나 과거 재생을 운영 폴더에 섞지 않는다.

## 후보 판단 화면

- 고정 화면의 기본값은 **마지막 저장일의 신규 유형1 후보만**이다. ‘유형1 전체’로 기존 관찰 종목도 볼 수 있다. 날짜가 오래돼도 오늘 후보라고 바꾸지 않는다. 전체 독립 경로 표는 별도 접힘 영역에 남긴다.
- ‘판단 차트 · 이후 경로’는 원래 저장 스냅샷의 60일 OHLC·거래량을 그린다. 선택된 날짜와 종목은 저장 명단으로 검증하고 스냅샷 해시를 대조한다. 파일 누락/변조 시 현재 데이터로 대체하지 않는다.
- 매매 경로가 있는 기존 관찰 종목은 최초 진입 판단일의 상세 화면으로 연결된다. 해당 날짜의 고정 차트에 이후 모형 가격선이나 결과를 섞지 않는다.
- 판단 이후 경로는 기본 접힘이며 별도의 가격 축이다. 첫 모형 진입과 청산 위치, 손절·목표선을 표시한다. 종료 이후 가격은 제외하고, 유효 봉이 없는 세션은 빈 칸으로 남긴다.
- 목록 가격 변화는 최초 진입 판단일(진입 없는 종목은 표시된 판단일) 종가 대비 **최근 저장 종가**다. 비교 기준일과 최근 가격 날짜를 함께 표시하며 실시간 가격 또는 매매 손익으로 표현하지 않는다. 실시간 스캔 링크는 기존 화면으로 이동한다.
- 읽기 전용 변경이다. 화면 조회 중 수집·스냅샷 저장·계좌 업데이트·주문은 실행하지 않는다. `format=json`의 기존 전체 기록 응답도 유지한다. 상세 날짜/종목을 지정한 JSON은 상세 차트 자료만 반환한다.
