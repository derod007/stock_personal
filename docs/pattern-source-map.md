# 원문과 구현 대응

이 표는 검토자가 A/B를 구분하도록 원문, 정의 문서, 코드를 나란히 둔 것이다. 하나를 정답으로 고르지 않았다. 수익이 난 거래를 올바른 구현으로, 손실 거래를 잘못된 구현으로 보지 않는다.

구분: **직접**은 파일에서 문장이나 조건식을 확인한 것. **추론**은 그 문장을 이 코드에 대응시킨 것. 프로그램이 정한 숫자는 “틀림”이 아니라 **수치, 원문 근거 확인 필요**다.

## 돌파 후 재지지

원문 목록에서 이 패턴과 같은 문장(“20봉 박스, 돌파 후 재지지, 다음 3거래봉”)은 확인하지 못했다. `BreakoutRetest.php` 주석은 “저자의 실제 매매라는 주장이 아니다”라고 직접 적는다.

| 구현에서 직접 확인 | 원문 |
|---|---|
| 최근 16봉 안에서 20봉 박스. 박스 높이는 ATR의 2~8배 | 확인한 원문에 없다. **수치, 원문 근거 확인 필요** |
| 종가가 박스 고점 + 0.1 ATR 위, 양봉, 거래량 1.2배 | 같은 표시 |
| 10봉 안에 재지지. 저가가 레벨+0.35 ATR 이하, 종가는 레벨 이상, 돌파봉보다 거래량이 작다 | 같은 표시 |
| 확인은 재지지봉 고점 회복, 양봉, 재지지봉 이상 거래량. 신호는 마지막 봉만 | 같은 표시 |
| 손절은 재지지 저점 − 0.2 ATR. 목표는 위 고점 또는 박스 높이 | 같은 표시 |
| 손익비 1.5, 지정가 3봉 | 1.5와 3봉은 **수치, 원문 근거 확인 필요**. 3봉은 재현 문서가 기존 `TradeSimulator`라고 직접 적는다 |

복기 글의 “추세 지지 이후 이탈, 저점 붕괴, 추세선 재터치”는 60분 숏 사례다. 이 일봉 롱 재지지와 같다고 **추론하지 않는다.**

## 상승 눌림

`TrendPullback.php` 주석은 “고정된 연구 가설”이라고 직접 적는다. 확인한 원문에 MA20, 0.75 ATR, 거래량 0.85, 직전 20봉 고점 목표를 적은 문장은 없다.

| 구현 | 표시 |
|---|---|
| 완료봉 45개. MA20이 5봉 전 MA20보다 높고, 최근 20봉의 저점·고점이 그 앞 20봉보다 높다 | **수치, 원문 근거 확인 필요** |
| 직전 5봉 저점이 MA20+0.75 ATR 이하 | 같은 표시. 눌림 시작일은 반환값에 없다. 차트에는 “구간 시작 좌표 미기록” |
| 눌림 3봉 평균 거래량 < 기준 20봉의 0.85 | 같은 표시 |
| 마지막 봉이 직전 고점 위 양봉이고 거래량이 직전보다 크며, 직전 종가가 그 앞 고점 이하(새 확인) | 같은 표시 |
| 진입은 확인 종가. 손절은 10봉 저점 − 0.2 ATR. 목표는 그 앞 20봉 고점. 손익비 1.5 | 같은 표시 |

원문의 “저점을 올려 주면 위로 간다”는 회복형 글의 문장이다. 눌림 코드의 “최근 20봉 저점이 더 높다”와 단어가 비슷하지만, 기간과 가격 정의가 같다고 확정하지 않는다. **판단이 필요하다.**

## 공통 차단과 따로 집계하는 것

직접 확인한 구현(`PatternReplay::blockers`): 급등 후 급락, 고점 붕괴, 일봉 하락 또는 주봉 하락(회복형은 주봉 하락이면 손익비 2). 점수로 필수 조건을 대신하지 않는다.

고점판독 글의 “세 번 돌파 뒤 실패하고 저점 이탈”은 매도 기법이다. `top_collapse`가 그 글의 구현인지는 정의 문장이 이 표의 원문 파일을 가리키지 않아 **판단이 필요하다.**

손익비 지정가 연구와 높은 저점형 watch/breakout은 재현 문서가 운영 추천과 따로 센다고 직접 적는다. 복기 글의 3:7 분할, SQQQ −2.5%, 60분 추세선은 이 일봉 엔진에 조건식으로 없다.

## 주봉

`TrendContext`는 완료 일봉만 쓰고, 기준일이 금요일 전이면 그 주를 빼며, 금요일 봉이 있어야 그 주를 넣는다. 20주 평균과 3주 기울기다. 복기 글의 60분 추세선과 같은 계산이 아니다.
