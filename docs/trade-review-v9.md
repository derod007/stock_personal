# 거래별 성과 분석 v9

머지 후 `git pull --ff-only` 하고 **모의 계좌 → 거래별 성과 분석**으로 들어갑니다. 기존 스케줄러, 계좌 ID, 전략 버전을 유지합니다. 새 수집이나 거래 재계산 없이 기존 계좌 기록을 읽습니다. 전략을 고정하는 src 파일은 변경하지 않습니다.

## 계산 기준

- 순손익: exit.net_pnl 원본. 순수익률: 순손익 / (실제 진입 수량 × 기록 진입가 + 기록 진입 수수료).
- 가격 차이 손익: 수량 × (기록 청산가 - 기록 진입가). 모형 수수료: 가격 차이 손익 - 기록 순손익. 기존 슬리피지는 체결가에 들어 있으며 별도 비용으로 다시 차감하지 않습니다. 실제 증권사 세금/비용을 검증한 수치는 아닙니다.
- R: 순손익 / 주문 당시 planned_risk. 갭 하락 등으로 -1R 미만이 될 수 있습니다.
- 청산 사유/진입 패턴: 주문 생성 시 snapshot에 저장한 origin과 pattern에 연결합니다. 같은 종목의 재진입은 order 이벤트 ID별로 분리합니다. 보유 중 거래는 완료 거래 집계에서 제외합니다.
- 각 그룹에 표본 수, 이익 건수, 순손익, 거래별 단순 평균 순수익률, 평균 R을 표시합니다. 그룹 평균은 계좌 수익률이 아니며, 사유/패턴 그룹을 더하면 중복됩니다. forward/catchup/replay를 섞지 않습니다.
- 연결한 완료 거래 수와 순손익을 계좌 closed_trades/realized와 대사해 불일치를 표시합니다.

## 최대 상승·하락을 범위로 표시하는 이유

진입 당일 고점은 진입 전일 수 있고 청산 당일 저점은 청산 후일 수 있습니다. 일봉만으로 정확한 MFE/MAE를 확정하지 않습니다.

1. 확인 구간: 진입·청산 체결가, 진입일 이후부터 청산일 이전까지 온전히 보유한 일봉 고저가, 청산하지 않은 보유일 종가.
2. 경계일 포함 범위: 진입일부터 청산일까지 전체 일봉 고저가와 체결가. 실제 체결 전/후 움직임을 포함할 수 있어 가능한 범위를 보여주는 참고값입니다.

동일 봉 진입·청산은 확인 구간에 두 체결가만 사용합니다. 보유 중이면 마지막 평가일까지 분석합니다. 두 값은 가격 기준이며 비용 차감 후의 실행 가능한 수익을 뜻하지 않습니다. 확인 구간의 하락에는 청산 슬리피지가 들어갈 수 있습니다. 체결·청산 날짜는 장중 시각이 아닌 해당 일봉의 세션 시각입니다. 모형의 ambiguous_bar를 함께 표시합니다.

## 손절 이후 5·10거래봉

손절 다음 관측 세션부터 N개를 사용해 N번째 종가/손절 체결가 변화율, N번째 종가의 원래 진입가 회복 여부, 기간 최고/최저가의 손절 체결가 대비 변화율을 표시합니다. 손절 당일은 제외합니다. 진입가 회복 여부는 비용 제외 가격 비교입니다. 이 결과는 손절을 없앴을 때의 전략 수익률이 아닙니다.

N개가 쌓이지 않으면 대기, 관측 세션에 품질 차단/누락이 있으면 계산 보류합니다. 나쁜 봉을 건너뛰어 유리한 N개를 고르지 않습니다. 완전한 거래소 휴일/정지 달력 검증은 아니며, 공급자와 계좌에 전혀 관측되지 않은 세션은 식별하지 못할 수 있습니다.

계좌에 보존된 history와 snapshot 품질을 사용하고 last_session 이후 데이터는 사용하지 않습니다. 계좌 중단 시 마지막 보존 기록까지만 분석합니다. 기업행동 가격 조정 미확인 등 기존 데이터 한계는 유지됩니다. 조건 변경이나 수익성 개선이 검증된 것으로 해석하지 마세요.

## CLI

```
php bin/paper_trade_report.php --account=paper-us --mode=forward
php bin/paper_trade_report.php --account=paper-kr --mode=replay
```

stdout으로 JSON을 출력하며 계좌를 수정하지 않습니다. 웹과 CLI는 같은 PAPER_STATE_DIR를 사용해야 합니다. 전체 기간을 분석합니다. 장기간 누적 시 전체 계좌 파일을 읽으므로 파일 크기에 따라 조회 비용이 늘어날 수 있습니다.
