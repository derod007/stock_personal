# 완료 일봉 재지지 계획 v1

## 목적과 적용 범위

작성자가 더 이상 글을 올리지 않아도 고정된 차트 가설을 과거 OHLCV에 적용해 평가한다.
작성자의 실제 매매를 복제하거나 수익 개선을 입증한 모델이 아니다. 알림·CSS는 작업 범위에서 제외했다.

`ChartPlanEngine`을 실제 조회/스캐너/게시 시점 재생/전체 차트 재생에서 공통 사용한다.
노라무·디깅온유·합침 모두 메인 주문 계획은 새 엔진 기준이다. 기존 작성자별 관점·가격은 참고로 남는다.
기존 점수는 패턴 유사성 설명용이며 확률이 아니고, 고득점만으로 진입할 수 없다.
기존 점수별 비중 확대/축소 지시는 신규 계획에 사용하지 않는다. 이번 버전은 신규 롱 진입 계획만 다룬다.
기존 보유 포지션 추적·자동 주문·자동 손절 변경은 구현하지 않는다.

## 고정된 가설 (작성자 원문의 확정 수치가 아님)

- 직전 20봉 고저 박스. 박스 폭은 돌파 전 단순 14봉 ATR의 2~8배.
- 종가가 박스 상단 + 0.1 ATR 초과, 양봉, 거래량은 돌파 전 20봉 평균의 1.2배 이상.
- 다음 10봉 안에 저가가 상단 + 0.35 ATR 이내로 접근하고, 종가는 상단 이상. 거래량은 돌파 봉보다 작아야 한다.
- 재지지 봉과 다른 이후 봉이 재지지 봉의 고가를 종가로 회복하고 양봉이며 거래량도 회복하면 확인.
- 확인 전 종가가 상단 - 0.5 ATR 아래면 무효. 10봉 초과 시 만료.
- 확인 당일에만 새 신호 생성. 이후 과거 확인 신호를 다시 신규 매수로 권하지 않는다.
- 다음 3거래봉 지정가 상한 = 확인 봉 종가. 손절 = 재지지~확인 구간 최저가 - 0.2 ATR.
- 목표 = 박스 상단 + 박스 폭. 그보다 가까운 위쪽 과거 고가가 있으면 그 가격을 우선한다.
- 손절 < 진입 < 목표이고 비용 전 손익비 1.5 이상인 경우만 `ready`.
- 기존 급등 후 급락/고점 붕괴 경고와 프로필의 레버리지 차단은 공통 엔진에서도 적용한다.

이 값들은 최적화하지 않은 연구용 초기값이다. 목표가를 늘려 손익비를 맞추지 않는다.
호가단위 반올림, 종목별 최소 주문·시장별 매매 비용, 거래정지·유동성별 체결은 추가 구현 대상이다.

## 시간과 데이터

일봉은 시작 시각이 아닌 거래소 마감 시각으로 이용 가능 여부를 판단한다.
국내 주식은 서울 15:30, 미국 주식은 뉴욕 16:00이며 DST를 반영한다.
조기 폐장일도 정규 마감까지 기다리는 보수적인 처리다. 선물·24시간 자산용 시간 모델은 아니다.
입력의 `available_at`은 검증된 봉 완료 시각(Unix timestamp 또는 ISO 날짜)일 때만 지정한다.
중복 완료 시각, 비정상 OHLC, `synthetic=true`, `is_complete=false`는 제외한다.
Yahoo 캐시 키를 바꿔 이전 합성/장중 봉 캐시를 재사용하지 않는다.
완료된 Yahoo 봉을 오래된 Naver 응답으로 덮지 않는다. Naver만으로 추가된 봉은 임시 봉으로 취급한다.
4일 넘게 오래된 완료 봉으로는 추천하지 않는다. 정확한 휴장일·거래정지 캘린더를 대체하지 않는다.
조회는 2년 일봉, 전체 전략 재생은 기본 5년 일봉이다. API가 제공하지 못한 구간은 복원하지 않는다.
수정주가/분할/상장폐지/생존편향 검증은 아직 별도다. 데이터 공급자의 과거 수정도 결과에 영향을 준다.

## 체결과 수익률

확인 봉 또는 게시 시점보다 나중에 완료되는 봉부터 평가한다. 과거 글의 가격은 체결가로 쓰지 않는다.
진입은 다음 봉부터 3봉 안의 지정가 터치가 필요하다. 시가가 이미 손절 이하 또는 목표 이상이면 진입 취소한다.
이는 시초에 상태를 확인한 조건부 계획이라는 가정이며, 전날부터 거래소에 상주한 주문의 실제 체결을 재현하지 않는다.
미체결 상태에서 같은 봉이 목표와 지정가를 모두 터치하면 선후를 몰라 취소로 처리하고 모호성을 기록한다.
체결 이후에는 목표 시초 갭을 먼저 처리하고, 일반적인 동시 손절/목표 터치는 손절 우선이다.
손절 갭 하락은 손절가가 아니라 더 낮은 시가에 슬리피지를 적용한다.
첫 손절/목표 이후 계산을 종료한다. 청산 없는 경우 체결 봉부터 N봉째 종가에 기간 청산한다.
기간이 부족하면 `incomplete`, 주문 유효기간이 아직 안 끝났으면 `pending`, 미체결이면 `unfilled`다.
이들을 수익률 평균·승률의 분모에 포함하지 않고 상태별 개수로 표시한다.
기본 편도 비용 10bp, 슬리피지 5bp는 실제 증권사 요율이 아닌 실험 가정이며 CLI로 변경 가능하다.
지정가 매수는 지정가를 넘지 않고 목표 지정가는 목표가로 체결한다. 시장 충격·거래량별 부분 체결은 미구현이다.

`ret_close_pct`, `avg_ret_close_pct`, `win_rate_close`는 구형 보고서 호환 키로 남지만 **첫 청산 비용 차감 성과**를 뜻한다.
새 코드는 `net_return_pct`, `avg_net_return_pct`, `win_rate`를 사용한다.
종목별 비중·동시 보유·자산곡선이 없으므로 평균 매매 수익률을 계좌 수익률로 해석하지 않는다.

## 평가 방법

`backtest_entries.php`는 full 기록의 게시 시점을 관찰 기준으로 쓰는 전략 재생이다.
작성자 실매매 성과가 아니며, 같은 종목/신호는 요약에서 중복 제외한다. 성과 평가는 전체 차트 재생을 우선한다.
`backtest_strategy.php`는 글 없이 모든 과거 완료 봉을 순서대로 조회한다.
종목당 하나의 대기 주문/보유 포지션만 평가하며, 기본 70%/30% 또는 `--split` 날짜로 기간을 분리한다.
앞 기간의 청산 계산에 뒤 기간 가격을 쓰지 않는다. 경계에서 미완료면 그 거래는 수익률에서 제외하고 뒤 기간은 새로 시작한다.
조건 선택에 사용한 종목·기간과 최종 확인용 종목·기간을 별도로 남겨야 한다.
현재 도구는 고정 규칙 평가만 수행하며 자동 학습·최적화·통계적 유의성 검정을 수행하지 않는다.

## 검증과 한계

`php tests/run.php`: 봉 마감/DST, 합성 봉 제외, 미체결, 손절 후 반등, 갭 체결,
동시 손절·목표, 미완료 구간, 비용, 돌파→재지지→확인, 손익비 거절,
미래 봉 독립성, 실시간/재생 일치, 오래된 데이터 차단 등을 결정적 인공 데이터로 검증한다.
PHP 8.5 WebAssembly 런타임에서 실행했으며 GitHub Actions는 Ubuntu의 네이티브 PHP로 재검증한다.
이 검증은 코드 동작을 확인하며 수익성·시장 데이터 품질·실거래 재현성을 입증하지 않는다.
실제 장기 OHLCV로 보고서를 새로 생성하기 전에는 기존 `backtest-latest.md` 성과를 새 엔진 성과로 사용하지 않는다.
