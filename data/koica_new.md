## 1. 자료구조론

“이름만 알면 되는 문제”가 많아요. 표만 깔끔히 외워도 점수 잘 나옵니다.

### 1.1 최근에는 이런 걸 물어봐요

| 유형           | 예시                              | 빈도     |
|----------------|-----------------------------------|----------|
| 정의 · 비교    | Stack / Queue / Deque 특징        | ★★★★★    |
| 순회 결과      | BST 삽입 후 중위 순회             | ★★★★★    |
| 복잡도 · Stable| Quick 최악 n², Merge = Stable     | ★★★★★    |
| 그래프 탐색    | DFS / BFS, Dijkstra 경로          | ★★★★     |
| 힙             | 배열 힙 삽입 후 index             | ★★★★     |
| 해시 충돌      | Chaining / 선형탐사               | ★★★★     |
| 균형 트리      | AVL 회전 (LR 등)                  | ★★★      |
| 표기 변환      | 중위 ↔ 후위                       | ★★★      |

> 7급 · 공기업은 코드 추적까지 나오기도 하지만,  
> KOICA 같은 객관식은 **정의 · 결과값 · 복잡도 표**가 핵심이에요.

### 1.2 구조 분류

| 구분   | 의미           | 예                              |
|--------|----------------|---------------------------------|
| 선형   | 한 줄로 연결   | 배열, 리스트, 스택, 큐, 덱      |
| 비선형 | 계층 · 네트워크| 트리, 그래프                    |

### 1.3 배열 vs 연결리스트

| 비교 항목      | 배열              | 연결리스트                |
|----------------|-------------------|---------------------------|
| 저장           | 연속 메모리       | 비연속 + 포인터           |
| 접근           | **O(1)**          | **O(n)**                  |
| 중간 삽입/삭제 | **O(n)** (밀기)   | 위치만 알면 **O(1)**      |
| 특징           | 캐시에 친화적     | 크기 조절이 유연함        |

### 1.4 스택 · 큐 · 덱 (가장 많이 나와요)

| 구조         | 규칙            | 어디에 쓰이나요?                    |
|--------------|-----------------|-------------------------------------|
| **Stack**    | **LIFO**        | Call Stack, DFS, 괄호, Undo         |
| **Queue**    | **FIFO**        | 프린터, **BFS**, Ready Queue        |
| **Deque**    | 양끝 입출력     | 슬라이딩 윈도우                     |
| **원형 큐**  | 끝 ↔ 처음 연결  | 배열 큐의 공간 낭비 해결            |
| 우선순위 큐  | 우선순위 순     | 보통 **Heap**, 삽입·삭제 O(log n)   |

기본 연산은 평균 **O(1)** 이라고 기억해 두세요.

### 1.5 트리 · BST · B-Tree / B+Tree

**용어 한 줄**  
Root / Parent · Child / Leaf(자식 없음) / Depth / Height / 차수(자식 수)

**BST 규칙**  
왼쪽 < 부모 < 오른쪽  
평균 탐색 O(log n), 한쪽으로 치우치면 O(n)

**꼭 기억!**  
BST를 **중위 순회**하면 → **오름차순 정렬**

| 순회     | 순서              | 팁                    |
|----------|-------------------|-----------------------|
| 전위     | Root → L → R      | 복사 · 전위표기       |
| **중위** | L → **Root** → R  | **BST = 정렬**        |
| 후위     | L → R → Root      | 삭제 · 후위표기       |
| 레벨     | 위→아래, 좌→우    | Queue 사용            |

| 비교     | B-Tree                | B+Tree                         |
|----------|-----------------------|--------------------------------|
| 데이터   | 모든 노드에 가능      | **Leaf에만**                   |
| Leaf     | 보통 연결 없음        | Leaf끼리 연결                  |
| 강점     | 일반 탐색             | **범위 검색**에 유리           |

### 1.6 그래프

| 비교   | DFS            | BFS                      |
|--------|----------------|--------------------------|
| 구조   | Stack / 재귀   | **Queue**                |
| 특징   | 깊이 우선      | 너비 우선, 최단경로(비가중) |

| 알고리즘       | 용도                    | 핵심                        |
|----------------|-------------------------|-----------------------------|
| Dijkstra       | 단일 출발 최단 (음수 X) | 탐욕 + 우선순위 큐          |
| Bellman-Ford   | 음수 간선 가능          | 완화 V−1회                  |
| Floyd-Warshall | 모든 쌍 최단            | DP, O(V³)                   |
| **Kruskal**    | MST                     | **간선** 중심, Union-Find   |
| **Prim**       | MST                     | **정점** 중심, 우선순위 큐  |

### 1.7 해시 · 정렬 · Big-O

**해시**  
Key → 해시함수 → 버킷  
평균 **O(1)** / 충돌이 심하면 최악 O(n)  
충돌 해결: Chaining(같은 슬롯에 리스트) / Open Addressing(빈 슬롯 찾기)

**정렬 (Stable · 복잡도 꼭!)**

| 정렬      | 평균         | 최악         | Stable | 한 줄 메모           |
|-----------|--------------|--------------|--------|----------------------|
| Bubble    | O(n²)        | O(n²)        | O      | 인접 교환            |
| Selection | O(n²)        | O(n²)        | X      | 최소(최대) 선택      |
| Insertion | O(n²)        | O(n²)        | O      | 거의 정렬에 강함     |
| Quick     | O(n log n)   | **O(n²)**    | X      | 피벗, 평균은 빠름    |
| Merge     | O(n log n)   | O(n log n)   | **O**  | 추가 메모리 필요     |
| Heap      | O(n log n)   | O(n log n)   | X      | 힙 이용              |

**Stable** = 같은 키의 상대 순서를 유지 (Bubble, Insertion, Merge)

**Big-O 빠른 순**  
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)

**이진 탐색** = 정렬이 **필수**, 시간 O(log n)

### 1.8 자료구조, 이것만 10개

1. Stack = LIFO / Queue = FIFO  
2. 배열 접근 O(1), 중간 삽입 O(n)  
3. BST 중위 = 정렬  
4. DFS = Stack, BFS = Queue  
5. B+Tree = Leaf만 데이터 + 범위검색  
6. 해시 평균 O(1), 충돌 = Chaining / Open Addressing  
7. Quick 최악 O(n²), Merge는 항상 O(n log n) + Stable  
8. Kruskal = 간선, Prim = 정점  
9. 이진 탐색 = 정렬 필수, O(log n)  
10. 완전 이진 트리 vs 포화 이진 트리 구분

## 2. 데이터베이스론

정의와 “단계 · 순서”만 정확히 외우면, 이 과목에서 점수를 많이 가져갈 수 있어요.

### 2.1 최근에는 이런 걸 물어봐요

| 유형              | 예시                            | 빈도     |
|-------------------|---------------------------------|----------|
| 정규화 단계 판별  | 부분종속 → 2NF, 이행 → 3NF      | ★★★★★    |
| 키 · 무결성       | PK / FK, 개체 · 참조 무결성     | ★★★★★    |
| ACID · 동시성     | Dirty / Phantom / Lost Update   | ★★★★★    |
| SQL 분류 · 순서   | DDL / DML, 논리 실행순서        | ★★★★★    |
| JOIN 결과         | INNER / LEFT                    | ★★★★     |
| Index · View      | 읽기↑ 쓰기↓, 가상 테이블        | ★★★★     |
| ER → 릴레이션     | 1:N 에서 FK 위치                | ★★★★     |
| 트랜잭션 회복     | UNDO / REDO, Checkpoint         | ★★★      |
| Degree / Cardinality | 속성 수 / 튜플 수            | ★★★      |

### 2.2 스키마 · 독립성

| 층     | 의미                |
|--------|---------------------|
| 외부   | 사용자 뷰           |
| 개념   | 논리 전체           |
| 내부   | 물리 저장           |

- 논리 독립성: 개념 ↔ 외부  
- 물리 독립성: 내부 ↔ 개념  
→ 아래가 바뀌어도 위가 덜 흔들리게 하는 거예요.

### 2.3 키 (거의 매회 나와요)

| 키             | 의미                                      |
|----------------|-------------------------------------------|
| Super Key      | 유일성만 (최소는 아닐 수 있음)            |
| Candidate Key  | 유일 + 최소인 후보                        |
| **Primary Key**| 후보키 중 선택된 기본키 (NULL · 중복 불가)|
| Alternate Key  | 후보키 중 PK가 아닌 것                    |
| **Foreign Key**| 다른 테이블의 PK를 참조                   |

### 2.4 무결성

| 종류         | 한 줄로 기억하기                         |
|--------------|------------------------------------------|
| 개체 무결성  | PK ≠ NULL, 중복 불가                     |
| 참조 무결성  | FK는 존재하는 PK 값 **또는 NULL**        |
| 도메인 무결성| 속성이 허용 범위 값만                    |
| 사용자 정의  | CHECK, Trigger 등                         |

### 2.5 정규화 (최고빈출!)

**A → B** : A가 정해지면 B도 정해진다

| 단계     | 무엇을 하나요?                              |
|----------|---------------------------------------------|
| **1NF**  | 원자값만 (반복 그룹 제거)                   |
| **2NF**  | 1NF + **부분 함수 종속** 제거               |
| **3NF**  | 2NF + **이행 함수 종속** 제거 (A→B→C)       |
| **BCNF** | 모든 **결정자가 후보키**                    |
| 4NF      | 다치 종속 제거                              |
| 5NF      | 조인 종속 제거                              |

시험에서는 보통 **1NF → 2NF → 3NF → BCNF** 까지만 나옵니다.

| 이상(Anomaly) | 의미           |
|---------------|----------------|
| 삽입 이상     | 넣고 싶은데 못 넣음 |
| 삭제 이상     | 지우다 같이 사라짐  |
| 갱신 이상     | 일부만 바뀌어 불일치 |

**반정규화**: 성능을 위해 일부러 중복을 허용하는 것 (최근에도 자주 언급돼요)

### 2.6 SQL

| 분류     | 역할         | 예                                       |
|----------|--------------|------------------------------------------|
| **DDL**  | 구조 정의    | CREATE, ALTER, DROP, **TRUNCATE**        |
| **DML**  | 데이터 조작  | SELECT, INSERT, UPDATE, **DELETE**       |
| **DCL**  | 권한         | GRANT, REVOKE                            |
| **TCL**  | 트랜잭션     | COMMIT, ROLLBACK, SAVEPOINT              |

> **함정**: TRUNCATE = DDL, DELETE = DML  
> 이 둘을 헷갈리면 틀리기 쉬워요!

**논리 실행 순서 (그대로 외우세요)**  
`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`  
(JOIN은 FROM 단계에서 처리)

| JOIN  | 결과                        |
|-------|-----------------------------|
| INNER | 양쪽에 있는 공통만          |
| LEFT  | 왼쪽 전부 + 매칭되는 오른쪽 |
| RIGHT | 오른쪽 전부 + 매칭되는 왼쪽 |
| FULL  | 양쪽 전부                   |

### 2.7 트랜잭션 · ACID · 격리

| 글자 | 이름         | 한 줄로                          |
|------|--------------|----------------------------------|
| A    | Atomicity    | All or Nothing (다 하거나, 말거나) |
| C    | Consistency  | 제약 · 규칙 유지                 |
| I    | Isolation    | 동시에 돌아도 독립처럼           |
| D    | Durability   | 커밋 후에는 장애에도 유지        |

| 문제               | 의미                              |
|--------------------|-----------------------------------|
| Dirty Read         | 아직 커밋 안 된 값을 읽음         |
| Non-Repeatable Read| 같은 행을 다시 읽었더니 값이 바뀜 |
| Phantom Read       | 다시 읽었더니 행이 추가/삭제됨    |
| Lost Update        | 갱신이 덮어써져서 사라짐          |

| 격리 수준         | Dirty | Non-Rep | Phantom | 메모           |
|-------------------|-------|---------|---------|----------------|
| Read Uncommitted  | O     | O       | O       | 가장 느슨함    |
| Read Committed    | X     | O       | O       | 실무에서 많이 씀 |
| Repeatable Read   | X     | X       | O       | Phantom은 가능 |
| Serializable      | X     | X       | X       | 가장 안전 · 느림 |

잠금: Shared(공유, 읽기) / Exclusive(배타, 쓰기) / **2PL**(확장 후 축소)

### 2.8 Index · View

| 객체   | 기억할 점                                      |
|--------|------------------------------------------------|
| Index  | 조회↑ / INSERT·UPDATE·DELETE↓ / 저장공간↑        |
| 클러스터드 | 데이터를 물리적으로 정렬 (테이블당 보통 1개) |
| 넌클러스터드 | 별도 구조가 데이터를 가리킴                |
| View   | 가상 테이블 (보안 · 독립성). 항상 복사본은 아님 |

### 2.9 DB, 이것만 10개

1. PK: NULL · 중복 불가 / FK: 존재 PK 또는 NULL  
2. 1NF → 2NF → 3NF → BCNF  
3. 이상 3종: 삽입 · 삭제 · 갱신  
4. ACID  
5. Dirty = Uncommitted / Phantom = RR까지 가능  
6. SQL 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY  
7. INNER = 교집합, LEFT = 왼쪽 전부  
8. Index = 읽기↑ 쓰기↓  
9. View = 가상 테이블

### 3.2 Process · Thread · 메모리

| 비교   | Program          | Process              | Thread                                      |
|--------|------------------|----------------------|---------------------------------------------|
| 정의   | 디스크上 실행파일| **실행 중** 프로그램 | 프로세스 안의 실행 단위                     |
| 메모리 | -                | 독립 주소공간        | Code · Data · Heap **공유**, **Stack만 독립**|
| 비용   | -                | 생성 · CS 큼         | 상대적으로 작음                             |

```
높은 주소
  Stack   ← 지역변수, 매개변수, 리턴주소 (↓ 성장)
  ↓↑
  Heap    ← malloc / new 동적할당 (↑ 성장)
  Data    ← 전역 · 정적 변수
  Text    ← 코드 (읽기 전용)
낮은 주소
```

| 상태    | 의미                    |
|---------|-------------------------|
| Ready   | CPU 대기 (준비 큐)      |
| Running | CPU 실행 중             |
| Waiting | I/O 등 사건 대기        |

흐름: New → Ready ⇄ Running → Waiting → … → Terminated  
**PCB**: 프로세스 정보 묶음 / **Context Switch**: 잦을수록 오버헤드↑

### 3.3 CPU 스케줄링

**비선점** (실행 중 강제 회수 X)

| 알고리즘 | 요지                         | 특징                      |
|----------|------------------------------|---------------------------|
| FCFS     | 도착 순                      | Convoy Effect             |
| SJF      | 짧은 작업 먼저               | 평균대기 최소, **기아**   |
| HRN      | (대기+서비스) / 서비스       | SJF 기아 보완             |

**선점** (강제 회수 O)

| 알고리즘 | 요지                         | 특징                              |
|----------|------------------------------|-----------------------------------|
| RR       | Time Quantum                 | 크면 ≈ FCFS, 작으면 CS↑           |
| SRT      | 남은 시간 최단               | 선점형 SJF                        |
| Priority | 우선순위                     | 기아 → **Aging**                  |
| MLFQ     | 다단계 피드백 큐             | 대화형에 유리                     |

### 3.4 교착상태 (Deadlock)

**발생하려면 아래 4개가 전부 만족해야 해요.**  
(시험에서는 한글만 / 영어만 / `한글 (영어)` 병기 모두 나올 수 있어요.)

1. Mutual Exclusion (상호배제)  
2. Hold and Wait (점유와 대기 / 점유 대기)  
3. No Preemption (비선점)  
4. Circular Wait (순환 대기 / 환형 대기 / 원형 대기)

| 전략       | 내용                                    |
|------------|-----------------------------------------|
| 예방       | 조건 중 하나 제거                       |
| **회피**   | 안전상태만 허용 → **Banker's Algorithm**|
| 탐지 · 회복| 발생한 뒤 프로세스 종료 · 자원 회수     |

**Starvation**(기아): 낮은 우선순위가 계속 못 씀 → **Aging**으로 해결
