# 비정상 일봉 응답 보존

2026-11-23 시가 0 조사에서는 변환 캐시만 남아 있어 Yahoo 원응답의 숫자 0과 빈 문자열·false·비숫자 문자열을 구분할 수 없었다. 이후 같은 문제가 생기면 원응답을 확인할 수 있도록 유형1 마감 수집과 독립 관찰의 Yahoo 요청에만 진단 저장을 켠다. 기존 캐시를 읽는 경우에는 새 원응답이 없으므로 보존하지 않는다.

## 범위와 저장

- HTTP 오류로 이미 거절된 응답은 대상이 아니다. 실제 수신 본문을 가격 변환 전에 검사한다.
- 일봉 응답의 마지막 완료 시각 봉에서 OHLCV 결측·비숫자·가격 0 이하·음수 거래량·고저 모순 또는 동일 타임스탬프 중복을 발견하면 저장한다. JSON 손상과 quote 구조 누락도 저장한다.
- 정상 응답, 5분봉, 아직 완료되지 않은 봉, 최신 완료 봉보다 오래된 봉의 오류만으로는 저장하지 않는다. 이 범위는 진단 보존 조건이며 매매·분류 규칙이 아니다.
- 기본 운영 경로는 `../stock-personal-paper/type1-observations/diagnostics/yahoo-response/prices/`와 `breakout-watch/`다. 별도 state-dir 사용 시 그 경로 아래에 둔다. 정상 조회만으로 폴더를 만들지 않는다.
- JSON 한 파일에 종목, 요청 range·interval, UTC 수신 시각, 봉 timestamp, 사유, 원본문 SHA-256, `body_base64`를 둔다. base64 해제 결과가 HTTP 응답 본문 바이트다. 헤더·인증정보는 기록하지 않는다.
- 같은 응답도 수신마다 별도 파일이다. 기존 기록은 덮어쓰지 않으며, 자동 삭제는 하지 않는다. 비정상 응답이 반복되면 용량이 늘 수 있다.
- 완성 전 파일은 `.pending`이고 완성 후 `.json`으로 이름을 바꾼다. 저장 실패나 중단 때 남은 `.pending`을 완료 증거로 사용하지 않는다.
- 저장 실패는 `Yahoo response evidence failed:` 오류 로그로 남는다. 기존 가격 처리, 캐시 폴백, 봉 검증 결과는 바꾸지 않는다.

## 검증과 한계

`php tests/yahoo_response_evidence.php`: 원본 바이트·해시·시각, 입력 종류 구분, 미완료 제외, 중복 수신 보존, JSON 손상, 범위 모순, timestamp 중복, 저장 실패 시 가격 결과 불변을 오프라인으로 검사한다. `type1-scan` CI에 포함한다.

이 변경으로 11월 23일 원응답을 복구하지 않는다. 과거 가격 파일과 관찰 일봉은 수정하지 않았고 운영 수집도 실행하지 않았다. 다음 예약에서 실제 비정상 응답이 발생해야 운영 증거가 생긴다. YahooChartClient 기본값은 진단 비활성이고 다른 수집 호출에는 적용하지 않는다.
