# 저장 신호의 가격 기반 후속 추적 복구

프로젝트 폴더에서 기존 모의 계좌와 같은 `PAPER_STATE_DIR` 환경으로 실행합니다.

```sh
php bin/paper_followup.php --account=paper-kr --saved-evidence
php bin/paper_rediagnose.php --account=paper-kr
```

첫 명령은 원본 관측과 해시·파일·종목·판정봉이 일치하는 기존 후속 가격 evidence를 읽어 재계산합니다. 네트워크 조회 없이 당시 evidence의 as-of까지만 계산합니다. 원본 감사 기록과 가격 evidence는 보존하고 followup의 실행별 이력 및 latest를 갱신합니다. 두 번째 명령은 최신 재진단 JSON을 만듭니다. 탈락 로그 → 기존 감사 로그 일괄 재진단 결과 보기 → JSON 내려받기로 공유할 수 있습니다. 원본 차이 표는 여전히 남으며 추적 처리 결과를 함께 표시합니다.

새 가격까지 갱신하려면 기존 `php bin/paper_followup.php --account=paper-kr` 명령을 사용합니다. `--prices=경로`는 지정한 로컬 가격을 사용합니다. `--saved-evidence`와 동시에 지정할 수 없습니다. 이전 정책으로 완료된 기록도 새 정책으로 한 번 검증합니다. 이후 같은 정책으로 완료된 기록은 기존처럼 동결합니다.

## 허용·차단 기준

- 원본 일봉 해시 검증은 유지합니다. 저장된 신호·거래량·손절·목표를 최신 값으로 다시 결정하지 않습니다.
- 새로운 감사 기록에는 실제 분석 종목코드 `analysis_symbol`을 기록합니다. 원래 요청 종목과 다르면 격리합니다. 과거 기록은 엔진 판정 문장의 시작에 명시된 종목코드를 추가 근거로 확인합니다. 근거가 없는 과거 기록은 `not_recorded`로 남기며, 동일 종목임을 검증했다고 주장하지 않습니다.
- 조회 범위 앞쪽의 누락 중 **판정봉보다 90일 넘게 오래된 연속 앞부분**만 원본에서 보존합니다. 추적 데이터와 겹치는 봉이 있어야 하고 판정봉 자체도 존재해야 합니다. 최근 누락·중간 누락·판정봉 누락·겹치는 이력 없음은 차단합니다. 90일은 달력일 기준의 보수적인 복구 제한이며 매매 기준이 아닙니다.
- 겹치는 모든 과거 봉의 OHLC는 정확히 같아야 합니다. 가격이 하나라도 다르면 `historical_revision_or_missing`으로 남습니다.
- 겹치는 봉의 거래량만 다르면 원본 거래량을 보존하고 양쪽 값을 로그에 남깁니다. 이는 저장 신호의 가격 결과를 관찰하는 정책이며 당시 거래량 조건의 유효성이나 데이터 공급자 일치를 보증하지 않습니다.
- 입력을 합치기 전에 추적 원본의 완료봉 중복·잘못된 OHLCV를 검사합니다. 원본 일봉 품질 검사와 미래 봉·체결·비용 검증도 유지합니다. 정규화로 오류가 사라지지 않게 합니다.

`reconciliation`에 정책 버전, 종목 근거, 원본/추적/정합 입력 해시, 보존한 앞쪽 봉 시각, 거래량 양쪽 값, 차단 차이를 저장합니다. 불일치가 확인된 KODEX 레버리지 같은 관측은 다른 종목으로 자동 치환하지 않으며 원본 그대로 격리합니다.

## 영향 범위

연구용 후속 추적과 지정가 성과 계산에만 적용합니다. 당시 추천 여부, 운영 매수 조건, 계좌 전략 버전·잔액·주문·보유내역을 변경하지 않습니다. 과거 전략 재계산에는 계속 원래 저장된 일봉을 사용합니다. 수익률 복구 건수는 실제 evidence에 따라 달라지므로 실행 결과로 확인해야 합니다.
