# 모의 계좌와 추천 기록 v7

## 설치 후 실제 기록 시작

Python 3 및 PHP가 명령행에서 실행되어야 합니다. 저장소 루트에서:

```bash
python bin/paper_daily.py --config=config/paper-us.json
python bin/paper_daily.py --config=config/paper-kr.json
```

명령은 일봉 수집 후 모의 계좌를 한 번 업데이트합니다. 이후 웹 화면의 **모의 계좌** 또는 paper.php에서 확인합니다.
페이지 조회는 수집/주문 상태를 변경하지 않습니다. 매 거래일 장 마감 뒤 같은 명령을 다시 실행하거나 사용자 PC 작업 스케줄러에서 실행할 수 있습니다.
이 PR이나 GitHub 검증만으로 사용자 PC의 일일 실행이 시작되지는 않습니다.

- 미국 기본 계좌: 가상 USD 100,000, MU/AAPL/MSFT/JPM/XOM
- 한국 기본 계좌: 가상 KRW 10,000,000, 삼성전자/하이닉스/현대차
- 기본 한도: 동시 주문·보유 합계 4개, 종목당 계획 위험 자산의 1%, 종목 투자금 20%, 업종 투자금 40%, 총 계획 위험 3%
- 원화·달러는 별도 계좌이며 환율 없이 합산하지 않습니다.
- 설정 파일은 config/paper-us.json, config/paper-kr.json입니다. 업종 분류는 예시 설정이며 사용자 목록에 맞춰 관리합니다.

수량은 정수이며 수수료·예상 손절 슬리피지와 현금/한도를 반영합니다. 한도 때문에 계획 위험보다 작게 배정될 수 있습니다.
한도는 신규 주문 시 적용하며 가격 변화로 기존 보유 비중이 넘었다고 자동 청산하지 않습니다.
갭 손실은 계획 위험을 초과할 수 있습니다.

## 어디에 무엇이 저장되는가

기본 기록 폴더는 저장소 상위 폴더의 stock-personal-paper입니다.
PAPER_STATE_DIR 환경변수로 웹 공개 경로 밖의 영구 폴더를 지정할 수 있습니다. CLI와 웹 PHP 프로세스가 같은 설정을 사용해야 합니다.
원본과 계좌 파일을 함께 백업하세요.

- 계좌ID-forward.json: 실제 기록한 시각 이후의 모의 처리
- 계좌ID-replay.json: 별도 과거 재현
- inputs/해시.data: 수집 당시 정규화 가격 및 제공되는 공급자 원본 응답
- 계좌별 잠금 파일: 중복 실행 시 원자적 업데이트 보호

원본 파일은 내용 해시로 보존되어 다음 수집이 이전 입력을 덮어쓰지 않습니다. 공급자의 최근 5년 조회 범위에서 오래된 봉이 빠져도 계좌의 원래 이력은 유지하고 새 봉을 이어 붙입니다. 겹치는 날짜의 값이 바뀌면 별도로 변경을 감지합니다.
추천 이벤트에는 종목·판단 시점·실제 기록 시점·진입/손절/목표·전략 버전·입력 해시·품질·출처가 고정됩니다.
기록은 애플리케이션에서 추가만 하며 전체 이력을 해시 연결로 확인합니다. 파일 소유자가 전부 다시 쓰는 공격까지 막는 외부 공증 저장소는 아닙니다.

## 미래 정보 사용 방지

처음 forward 실행은 가장 최근 완료 거래일의 판단만 저장합니다. 과거 전체를 실제 기록한 추천으로 만들지 않습니다.
모의 체결은 **기록 시각 이후에 개장한 완전한 거래일**부터 허용합니다. 장중에 실행해 이미 지나간 시가/저가로 체결시키지 않습니다.
실행하지 못한 기간의 snapshot은 catchup으로 표시하고 신규 주문을 만들지 않습니다. 이전에 기록한 대기 주문/보유 종목만 이후 봉으로 처리합니다.
수집 당시 미완성이던 봉은 며칠 뒤 파일을 다시 읽었다고 완료 봉으로 승격하지 않습니다. source fetched_at과 거래소 마감 시각을 함께 사용합니다.

## 데이터 품질

원본/공급자 파일 해시를 확인합니다. 최근 90일 이내 잘못된 OHLCV, 중복 봉, 해당 거래일 누락, 60봉 미만 자료는 해당 종목의 모의 거래를 차단합니다.
price-crosscheck.json을 입력 폴더에 함께 제공하면 그 파일의 최근 공급자 불일치도 차단 사유에 반영합니다. 기본 일일 수집은 모든 가격을 두 공급자에서 자동 조회하는 기능이 아닙니다.
오래된 잘못된 봉 제외 및 미확인 기업행위 보정은 경고로 남습니다. 경고 상태를 검증 완료 가격으로 표시하지 않으며 연구용 모의 처리는 허용합니다.
최신 가격을 확인할 수 없는 보유 종목은 마지막 유효 가격으로 추정하고 계좌를 중단합니다. 누락 기간의 손절/체결 경로를 추측해서 다음 날 자동 재개하지 않습니다. 그날의 측정 낙폭은 산출하지 않습니다.

## 계좌 동작

- 대기 주문은 현금을 예약하고 체결 때 실제 금액과 수수료를 차감합니다.
- 같은 종목 중복, 현금 부족, 동시 보유·업종·위험 한도로 제외한 사유를 기록합니다. 동시 후보는 재현 가능한 티커 사전순으로 처리하며 점수 최적화 순위가 아닙니다.
- 기존 공유 TradeSimulator의 지정가 3봉 유효, 최대 보유 20봉, 구조 손절/첫 목표, 편도 수수료 10bp·슬리피지 5bp를 사용합니다.
- 기업행위에 따른 주식 수 조정, 실제 호가 단위, 부분체결, 공휴일 단축장 등은 아직 모델에 포함되지 않습니다.
- 현금, 예약금, 실현 손익, 종가 기준 미실현 손익, 평가 자산, 유효 종가 기준 최대 낙폭을 표시합니다.
- 주식 평가금액은 종가 기준이며 예상 전량 청산 수수료를 미리 차감한 금액이 아닙니다. 미래 수익률 검증에는 완료 거래 수와 데이터 누락을 함께 보세요.

## 버전·가격 변경 처리

src 파일 묶음과 설정 해시를 계좌에 고정합니다. 코드나 설정이 바뀌면 기존 계좌를 조용히 다른 전략으로 이어가지 않습니다.
새 설정 파일에서 새 id를 지정해 별도 계좌를 시작하거나, 기존 계좌는 기존 코드 버전으로 유지하세요. 화면에는 이전 계좌도 ID로 조회할 수 있습니다.
이미 기록한 시점의 입력이 변경되면 data_revision 이벤트를 남기고 계좌 처리를 중단합니다. 기존 추천/거래를 덮어쓰거나 성과를 다시 계산하지 않습니다.
중단된 계좌는 원본 보관 자료와 변경 데이터를 확인한 뒤 새 계좌로 시작합니다. 처음 현금/보유를 이전하는 자동 이관 기능은 없습니다.
