# recovery_close 한 조건 제외: 연구 계좌 비교 v1

개발 기준: main `8de7233`. 결과를 보기 전에 이 프로토콜과 연구 코드를 고정한다.
이미 opportunity-v1 결과와 상위 이익 사례를 보고 선택한 탐색 실험이다. 독립 검증이나 운영 변경 근거로 확정하지 않는다.

## 단 하나의 개입

상승 눌림의 확인식에서 `last.close > prev.high`만 필수 조건에서 제외한다.
`gates.recovery_close`에는 실제 참/거짓을 그대로 남긴다. 나머지 상승 구조, MA20 근접,
거래량 감소·회복, 양봉, 새 확인, 손익비, 목표·손절, 세 패턴 선택 순서, 상위 추세와 공통 위험은 유지한다.
연구 전용 정적 복사본에만 적용한다. `assertMirror`가 운영 소스와 허용된 텍스트 변경 이외의 차이를 거부한다.
`src/`와 운영 지문은 수정하지 않는다. 기존 recovery 추천이 pullback으로 교체되는 경우도 연구에 포함한다.

## 계좌와 입력

PR #76의 244세션, 일별 KRX TOP100, v2 일봉, 전체 섹터 맵을 사용한다. 합집합을 일일 후보로 사용하지 않는다.
초기 1억원, profile account1, 상위 추세 적용. 설정은 기존 recovery-v1에서 계좌 ID만 바꾼다.
비용·수량·현금·보유·위험·섹터 한도·종목 순서·대기 관리·청산 규칙을 유지한다. 마지막 보유는 강제 청산하지 않는다.

별도 계좌:
- `<PAPER_STATE_DIR>/history-account/hist-rc-account-v1-baseline/account-replay.json`
- `<PAPER_STATE_DIR>/history-account/hist-rc-account-v1-variant/account-replay.json`
- 산출: `<PAPER_STATE_DIR>/history-research/recovery-close-account-v1/`

기존 운영/연구 계좌와 데이터셋에는 쓰지 않는다. 추가 수집 없음.
기준 파일 LF 해시·데이터셋 원본 해시는 frozen-inputs.json, 봉별 해시·설정·연구 코드·프로토콜 해시는 최초 inputs.json에 고정한다.
이후 변경은 이어하기를 거부한다. 원래 파일과 고정 해시를 결과에 맞춰 고치지 않는다.
대안 저널의 `plan_source=injected_test`는 기존 연구 러너의 콜백 경로 이름을 보존한 것이다.
이 실험은 가짜 추천 주입이 아니라 연구 엔진 전체 재계산이다. inputs.json과 comparison.json에 이 차이를 명시한다.

## 실행 순서와 통과 조건

1. validate: 무결성·후보·전체 섹터 맵·지문·소스 복사본 점검. 쓰기 없음.
2. baseline: 기본 8세션 소규모 실행 후 잔여 244세션까지 이어하기.
3. 기준 계좌의 전체 거래 및 일별 로그, 최종 요약을 PR #76 저장본과 비교한다.
   계좌 ID만 제외한다. 수량·날짜·문자열·키는 동일, 실수는 절대 오차 1e-7 이하.
   이벤트 장부 대사와 신규 주문 as-of 엔진 대조도 통과해야 한다.
4. variant: 매 실행마다 기준 244세션 전체 일치와 장부 대사를 재확인한다. 실패 시 대안 계좌를 만들거나 진행하지 않는다.
5. 대안도 8세션 후 잔여 실행. 보고서는 양쪽 244세션 완료·정지 없음·장부 및 주문 검증 통과 뒤 생성한다.
   같은 날짜 재실행은 새 저널 이벤트를 만들지 않는다.

## 비교 항목

총자산·현금·실현/미실현·종가 최대낙폭, 전후 122세션 자산 변화, 종료/보유/취소/대기,
추가/누락/패턴 교체/동일 주문 및 동일 종목·신호일의 수량·체결·청산 변화.
기존 이익 거래가 사라지거나 달라졌는지 모든 주문의 원값과 대안 신호·실제 거절 사유로 확인한다.

금액은 계좌 자산 변화와 거래 손익을 구분한다. 종료되지 않은 거래를 0%로 처리하지 않는다.
