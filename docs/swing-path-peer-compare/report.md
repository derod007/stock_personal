# 같은 날·같은 시장 비교 결과

계획은 `protocol.md` 그대로다. 1차 294개와 2차 399개 보존 신호를 사용했고 신호를 다시 재생하지 않았다. 기존 236종목에서 같은 시장, 확인일까지 완료 봉 5개 이상, 확인일 완료 봉이 있는 종목을 후보로 삼았다. 각 신호 종목 자신은 제외했다. 이후 봉이 없다는 이유로 후보를 빼지 않았다.

주 지표는 각 신호의 20거래일 종가 변화율에서 같은 날 비교 종목의 완료된 변화율 중앙값을 뺀 **차이의 중앙값**이다. 단위는 %p이며 시장지수 초과수익이나 비용 반영 수익률이 아니다. 양수 비율은 매매 승률이 아니다.

## 20거래일 결과

1차:
- 손익비 조건 통과: 중앙값 +0.282%p, 양수 49/95 (51.58%). 원래 신호 98건 중 미확정 3건 제외.
- 손익비 부족: 중앙값 -1.009%p, 양수 60/129 (46.51%). 원래 신호 131건 중 미확정 2건 제외.
- 저항 미확정: 중앙값 -0.950%p, 양수 31/65 (47.69%). 원래 신호 65건 모두 사용.

2차:
- 손익비 조건 통과: 중앙값 -2.150%p, 양수 46/104 (44.23%). 원래 신호 107건 중 미확정 3건 제외.
- 손익비 부족: 중앙값 +2.501%p, 양수 116/212 (54.72%). 원래 신호 212건 모두 사용.
- 저항 미확정: 중앙값 +4.009%p, 양수 45/80 (56.25%). 원래 신호 80건 모두 사용.

두 기간 모두 완료된 비교 종목이 0개여서 추가로 제외한 신호는 없다. 신호 경로의 미완료도 없다. 비교 종목 자체의 미확정은 그대로 남기고 그 값은 중앙값에서 제외했다. 모든 신호별 비교 대상·완료·미완료·미확정 수는 보존 결과에 있다. 5·10일 보조 결과도 같은 파일에 남겼다.

손익비 조건 통과 집단이 같은 날 같은 시장의 비교 종목보다 일관되게 높다는 근거는 나오지 않았다. 1차의 작은 양수 차이는 2차에 유지되지 않았다. 그렇다고 손익비 부족이나 저항 미확정 집단을 새 추천 규칙으로 채택하지 않는다. 이미 결과를 본 자료이고, 같은 종목·같은 날짜·겹치는 구간은 독립 표본이 아니다. 시장 전체 표본이 아니며 업종과 규모도 맞추지 않았다. 통계적 유의성이나 인과 효과를 검증하지 않았다.

## 입력과 계산 검증

- 1·2차 각각 묶음 manifest의 바이트 해시, 묶음 종목·달력 해시와 inputs의 일치, 정확한 236종목의 단일 처리, 재합산과 보존 observations·summary의 일치를 확인했다.
- 1차 observations는 재합산과 배열 순서가 달랐다. 종목·돌파 기준선·돌파일 키로 대조해 값이 같음을 확인했다. 중복 키는 허용하지 않는다.
- 실제 일봉·달력은 해당 실험 입력 해시와 일치했다. 실행 전후에도 바뀌지 않았다. 기존 일봉·원본·실험 결과·계좌·예약은 쓰지 않았다.
- 별도 Python 검산으로 저장 봉과 달력에서 후보 선정 및 5·10·20일 가격 경로를 다시 계산했다. 1차 19,600개, 2차 27,296개 종목·확인일 경로와 693개 신호의 자기 종목 제외 중앙값, 차이, 집계가 일치했다. 이는 같은 자료·규칙의 산술 검증이며 새로운 독립 실험이 아니다.
- 임시 자료 테스트는 자기 종목 제외, 같은 날 신호별 중앙값 차이, 시장 분리, 미래 봉을 후보 선정에 사용하지 않음, 늦은 자료 가용 시각, 첫 봉 누락, 잘못된 봉, 기간 미완료, 관찰 종료 이후 봉 제외, 해시 불일치 중단을 포함한다. 기존 스윙 연구·집계·보존 묶음 검사도 통과했다.

## 실행 및 보존

실행 명령은 `php -d memory_limit=512M bin/swing_peer_compare.php --experiment=first`와 `--experiment=second`다. 계산 코드 내용은 커밋 `782de76601dfd600c888f7c65ad72fc11201c96d`에 해당한다. 각 결과 안에는 실제 읽은 코드·계획·자료의 바이트 해시가 있다. 계산 후 CLI 출력 형식만 gzip으로 바꿨으며 계산 값은 바꾸지 않았다.

1차는 약 11.62초, 최대 할당 메모리 228MiB, 2차는 약 18.13초, 300MiB였다. PHP의 `memory_get_peak_usage(true)`이며 운영체제 전체 메모리 측정은 아니다.

`first.json.gz`, `second.json.gz`는 계산 결과 원본 JSON을 무손실 압축한 파일이다. 신호별 비교 결과와 시장·확인일별 후보 목록, 제외 이유, 비교 종목별 가격 경로를 포함한다. `manifest.json`에 압축 파일과 압축 해제 JSON의 해시·크기·출력 시각·실행 명령을 남겼다. 압축 해제 후 원본 JSON 바이트와 같음을 확인했다.

`php tests/swing_peer_compare.php`는 임시 자료 테스트와 보존 압축 결과의 해시·신호별 중앙값 산술을 검사한다. 원본 일봉은 Git에 없으므로 클론만으로 가격 경로를 다시 계산할 수는 없다. 실제 비교 CLI는 기존 결과가 있으면 계산 전에 중단한다. 보존 파일을 지우거나 기존 입력을 갱신해 이 결과를 덮어쓰지 않는다.

다음 단계는 현재 규칙의 추천 기능 확대가 아니라, 원문에서 확인되는 판단 조건과 구현 가정의 대응을 점검하는 것이다. 이번 결과를 보고 임계값이나 기간을 조정하지 않았다.
