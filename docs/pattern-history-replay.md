# 고정 종목군의 날짜별 패턴 재현

`bin/paper_pattern_replay.php`는 준비된 일봉을 과거 판정일마다 잘라 현재 규칙을 실행하는 오프라인 연구 도구다. 저장 스캔 5일만 재평가하는 `paper_historical_research.php`와 구분한다. 원본·계좌·운영 연구 상태는 쓰지 않으며 네트워크 접근도 하지 않는다.

## 실행

PR #54 데이터 준비가 끝난 데이터셋 폴더를 지정한다. 아래 Windows 경로는 이번 첨부 데이터셋의 원래 위치다.

```powershell
php -d memory_limit=512M bin/paper_pattern_replay.php --dataset-dir="C:\Users\acdun\Desktop\dev\stock-personal-paper\history-research\kr-saved-scan-20261009" --profile=account1 > pattern-replay-20261008.json
```

진행 상황은 표준 오류에 종목당 한 줄로 나오고, 결과 JSON만 표준 출력으로 나온다. 원본 `verify` 실패 시 중단한다. 기본 프로필은 `account1`, 상위 추세 적용은 활성화다. `custom` 또는 `isa`는 별도 실행으로만 비교한다. 평가 시작일은 dataset.json에 기록된 평가 시작일을 쓰고, 그 기록이 없으면 기준일의 12개월 전이다. 기준일 이후 봉은 넣지 않는다. 첫 데이터셋은 2025-10-08~2026-10-08이다.

## 신호와 품질

- 수집 완료이면서 데이터셋 전체 품질 보류가 아닌 종목만 사용한다. 이는 최종 수집 시점에서 정한 연구 대상이다. 따라서 품질 제외 자체도 당시 실시간 종목 선정 재현은 아니다.
- 매일 원본의 해당 종가 시각까지 봉만 `PaperQuality`와 엔진에 전달한다. 잘못된 OHLC를 먼저 제거해서 품질 차단을 우회하지 않는다. 60봉 미만은 차단하며 240봉 미만 여부는 이벤트의 `completed_bars`로 확인한다. 모든 패턴에 새로 240봉 필수 조건을 강제하지 않는다.
- 완료 시각을 한 번 계산해 `available_at`에 기록하는 것은 연구 입력의 정규화다. 원본 가격·거래량은 바꾸지 않고 원본 파일 해시는 별도로 보존한다. 이벤트 `input_hash`는 이 정규화된 과거 입력의 해시다.
- 3개 추천 패턴의 자체 진단과 종목 최종 판정을 각각 보존한다. `signal_at`이 그날인 확인 이벤트만 등록한다. 회복형의 목표 없음/가격 무효도 확인 이벤트로 기록하되 거래로 만들지 않는다.
- 재지지는 돌파·재지지 시각, 회복형은 저점 이탈 시각, 상승 눌림은 엔진의 fresh confirmation을 만족한 확인 시각으로 식별한다. 같은 식별자의 후속 반복은 제거한다.
- 높은 저점형은 기존 `PaperHigherLowResearch::inspect`를 사용한다. 구조 ID와 watch/breakout 단계별 최초 적격 관측만 등록한다. 단계 확정이 평가 시작 전이거나 품질 차단 중이면 최초 적격 관측이 늦을 수 있다. `stage_confirmed_at < session`과 집계 `late_first_observations`로 이를 구분하며 수익률을 앞선 확정일로 소급하지 않는다.
- 각 패턴의 공통 위험·상위 추세 차단은 독립적으로 기록한다. 기존 엔진의 선택 우선순위는 그대로이며 비선택 패턴의 독립 통과를 운영 추천으로 바꾸지 않는다. 점수로 필수 조건을 대체하지 않는다.

## 후속 결과

가격 관찰과 모의 거래는 별도다.

1. `horizons`: 관측 종가 대비 이후 1/3/5/10/20봉 종가 변화, 최대 상승·하락. 패턴 자체 확인 이벤트에는 최종 차단된 사례도 포함된다. 그룹의 raw_status와 blockers를 함께 읽는다.
2. `independent_ready`: 해당 패턴 자체 ready 및 독립 공통 차단 통과 시의 가상 지정가 거래. 여러 패턴이 같은 날 통과하면 별개다.
3. `selected_baseline`: 현재 엔진에서 실제 선택되고 최종 ready인 계획만 사용한다. 위 독립 거래와 겹칠 수 있으므로 둘을 더하지 않는다.
4. `rr_limit`: 기존 `PaperRrAudit`가 선정한 손익비 보완 지정가 연구만 사용한다. 기존 추천과 별도이며 연구 목적이다.
5. 높은 저점형은 가격 관찰만 한다. 손절·목표·주문을 임의로 추가하지 않는다.

이후 봉은 각 원본에 존재하는 완료 세션만 사용하며 데이터셋 기준일을 넘지 않는다. 잘못된 후속 봉·중복 세션을 없애고 다음 봉을 당겨 세지 않는다. 오류 봉을 포함하는 관찰 기간은 `quality_blocked`, 미성숙 기간은 `pending`이다. 더 짧은 기간이 이미 유효하게 끝났다면 그 결과는 유지한다.

모의 거래는 기존 `TradeSimulator`의 다음 3봉 지정가·체결 후 최대 20봉·고정 손절/목표·일봉 순서 불확실성 처리·비용 모형을 그대로 사용한다. 따라서 최대 22개 후속 세션을 확보한다. 첫 오류 봉 앞까지만 계산하며 이미 종료된 거래는 보존하고 미종료 거래는 `future_quality_blocked`로 표시한다. 원래 존재하지 않는 거래일은 만들지 않는다.

## 해석 범위

- 현재 확보한 고정 종목군의 과거 재현이다. 당시 TOP100·상장/상폐 전체 시장·당시 실제 가격 제공 상태를 복원하지 않는다.
- 지금 받은 수정·복구 이력을 포함한 가격으로 계산하므로 당시 실제로 볼 수 있었던 가격과 같다는 보장은 없다. 종가 복구 종목은 결과 보고서에서 별도 구분한다.
- 종목별 일봉 수, 패턴 이벤트 수, 실제 모의 체결 종료 수는 다른 분모다. 중복 신호를 제거해도 같은 종목·날짜의 수익률과 겹친 보유 기간은 서로 독립적이지 않다.
- 계좌 자금·동시 보유·업종 비중 제한을 적용하지 않는다. 개별 거래의 수익률을 합쳐 계좌 수익률로 표시하지 않는다.
- 조건을 바꾸지 않은 탐색 연구다. 결과를 보고 조건을 조정하면 새로운 기간에서 다시 검증해야 한다.

검증: `php tests/pattern_replay.php`. 미래봉 영향 차단·원본 보존·과거 품질 차단·공통 위험·후속 봉 오류와 중복·3번째 봉 체결 후 20봉 보유·관찰 중복 제거 및 단계 분리·미완료 표본 분모를 검사한다.
