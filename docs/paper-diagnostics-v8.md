# 실행·추천 진단 v8

기존 모의 계좌 화면의 **실행·추천 진단** 링크를 사용합니다. `paper_diagnostics.php?account=paper-us` 또는 `account=paper-kr`로 직접 열 수도 있습니다. CSS/알림이나 매매 조건은 변경하지 않습니다.

## 적용

PR 머지 후 기존 프로젝트에서 `git pull --ff-only` 하세요. 기존 스케줄러가 `bin/paper_daily.py`를 실행하고 있다면 명령은 그대로 사용할 수 있습니다. PHP CLI를 직접 예약했다면 실행 상태 로그를 남기려면 예약 명령을 Python 래퍼로 바꿔야 합니다.

```
python bin/paper_daily.py --config=config/paper-us.json
python bin/paper_daily.py --config=config/paper-kr.json
```

프로젝트 밖에서 실행할 때는 스크립트 경로를 절대 경로로 지정합니다. 상대 config 경로는 프로젝트 기준으로 해석합니다. PHP는 스케줄러 계정의 PATH에 있어야 합니다. 웹과 예약 작업은 같은 PAPER_STATE_DIR 및 파일 접근 권한을 사용해야 합니다. 미설정 시 기존처럼 프로젝트 옆 stock-personal-paper 폴더를 사용합니다.

## 실행 상태

각 실행은 별도 `runs/<account>-forward/<run-id>.json`에 시작, 현재 단계, 종료, 결과를 원자적으로 저장합니다. 수집과 계좌 갱신은 각 30분 제한입니다. 기존 계좌 파일/전략 해시는 변경하지 않으며 별도 계좌 생성이 필요 없습니다.

- 정상·첫 실행 관측: 이전 성공 실행 로그가 없어 갱신 여부 비교 불가
- 정상·새 거래일 갱신: 이전 성공 로그보다 계좌 거래일 전진
- 정상·새 거래일 없음: 같은 거래일 재실행. 휴장/장중일 수 있고 수집 데이터가 오래됐을 수도 있으므로 데이터 품질과 마지막 거래일을 함께 확인
- 실패: 수집 또는 계좌 단계의 예외/비정상 종료
- 계좌 중단: CLI가 중단 상태를 반환. 스케줄러에도 종료 코드 2 전달
- 완료 기록 없음: 시작 후 3,700초 이상 완료 로그가 없음. 강제 종료 가능, 실제 프로세스 종료를 확정하는 표시는 아님

스케줄러 자체가 실행되지 않으면 프로그램은 로그를 쓸 수 없습니다. 마지막 실행 경과 시간을 보여주되 예정 시각/휴일을 모르므로 누락이라고 단정하지 않습니다. 버전 적용 이전 실행도 추정하지 않습니다. 설정 파일을 읽기 전 실패, 로깅 폴더 접근 실패, Python 시작 실패는 스케줄러 자체 이력에서 확인해야 합니다. 수집기의 종목별 실패가 전체 프로세스 종료 코드에 반영되지 않는 경우는 계좌의 데이터 품질 집계로 확인합니다.

로그의 error_type과 단계는 웹에서 확인하고 상세 stderr는 예약 작업 로그에서 확인합니다. 로그는 자동 삭제하지 않습니다. 오래된 운영 로그는 백업 후 별도 관리할 수 있으나 계좌 원본 파일은 수정하지 마세요. 동시 실행은 수집 임시 폴더를 분리하며 계좌 저장은 기존 잠금을 사용합니다. 수집 임시 파일은 실행 후 정리하고, 계좌에 사용한 원본은 기존 입력 보관 기능으로 유지합니다.

## 추천 집계 해석

계좌 마지막 기록 거래일을 기준으로 최근 30일을 집계합니다. forward/catchup/replay를 분리하며, 과거에 생성된 주문의 체결/취소/청산은 실행 결과로 따로 표시합니다. 평가 건수는 종목×거래일 기준입니다.

기존 decision은 처음 걸린 제외 조건 하나만 기록합니다. 현금·위험·업종 한도는 기존 통합 사유를 그대로 표시하며 사후에 세부 원인을 지어내지 않습니다. 진입 조건 미충족은 같은 시점 snapshot의 plan.reason을 연결합니다. 품질 차단 사유는 평가당 여러 개일 수 있으므로 합계가 평가 건수와 다를 수 있습니다. 데이터 경고는 기존 모의 계좌 화면에서 확인합니다.

주문 생성 기간과 체결 기간이 다르므로 이 집계만으로 체결률/승률을 계산하지 않습니다. 이번 변경은 실행과 추천 제외 진단 단계이며 거래별 최대 상승/하락 및 후보 전략 비교는 포함하지 않습니다.
