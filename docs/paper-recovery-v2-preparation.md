# KR recovery v2 준비 — 2026-11-25

이 변경은 새 계좌 설정과 기존 청산 보호의 적용 준비다. 운영 계좌를 만들거나 예약을 전환하지 않는다.

## 기존 중단 원인

`paper-kr-recovery-v1-forward.json`은 2026-10-22 20:23 KST에 `historical_revision`으로 중단됐다. 10월 21일 시작한 계좌이고, 체결 보유는 없으며 036540.KQ 미체결 주문 938주가 남아 있다. 현금은 100,000,000원이다. 중단 해제, 주문 취소, 기존 장부 재작성은 하지 않는다.

운영 `inputs/`에 남은 두 자료를 완료 시각으로 정규화하고 기존 이력과 합친 뒤 판단일 이하로 잘라 해시를 재현했다.

- 10월 21일 자료: `fd64ccd504b889b4d5eac048d14aa4a115b6f56933c79c3938844d919b1d4327.data`
- 10월 22일 자료: `55dca2829dfc7dd0d9165bdb7eb0b39a5a14b5e81d0bc21e33a9f0039f34aba1.data`
- 이전 입력 해시: `75703985f751e3566e0ecc18b815c059994f4597244ecdc2058485891600397e`
- 새 입력 해시: `3543f7b9f73b39fd7ddfdc186f37ac3278a60b0b8f3c0b684f19f8893242caf8`

차이는 2026-10-21 봉의 거래량 한 필드, 5,111,817 → 5,090,373이다. 두 해시는 저장된 중단 이벤트와 일치한다. 이전의 변경 0건 보고는 비교 종목 누락 때문이며 PR #156은 보고만 고쳤다. 현재도 과거 거래량 변경은 중단 사유다. 공급자가 값을 바꾼 이유까지 확인한 것은 아니다.

이전 임시 실행에서 같은 보존 입력으로 새 ID도 다음 날 같은 수정에서 중단되는 것을 확인했다. 따라서 새 ID는 자료 수정 문제의 해결책이 아니다.

## 준비한 변경

`config/paper-kr-recovery-v2.json`은 v1 설정에서 ID만 다르다. 자본, 종목 선정, 위험 한도는 그대로다. `half_risk_v1` 대상을 v1·v2 두 ID로 명시한다. KRW forward에만 적용하며 활성화 이후 신규 체결에만 적용한다. 1R 종가 도달 후 다음 봉부터 잔여 위험 0.5R, 기존 비용·갭·동봉 처리와 보유 주문 보존은 바뀌지 않는다.

전략 파일이 바뀌므로 지문도 바뀐다.

- 이전: `2303a1b6c59353e3e53f5b49d011adb8e82a184e8cd9b31d86ed541c712b1c3f`
- 준비 코드: `d19460b01938f173521c3086a26338c5c2fce6966dffadfd6d158e3fe9a897ee`

일반 호환 예외는 추가하지 않았다. 기존 명시적 forward 전환 목록에 이전 지문을 추가하고, 이미 허용된 `934012…` 전환의 도착 지문을 갱신했다. 중단되지 않은 forward 계좌만 기존 주문·이력을 보존하며 버전을 전환할 수 있다. 중단 계좌, 알 수 없는 지문, 과거 replay는 이 전환을 허용하지 않는다. 현재 운영 KR·US 장부는 모두 중단 상태이며 이번 작업에서 수정하지 않았다. 고정된 목표 추적 기록의 버전 불일치도 이번 변경으로 해결하지 않는다.

## 확인과 이후 전환 조건

`tests/recovery_v2.php`는 임시 상태에서 v1/v2 보호 청산의 동일한 가격·이벤트, 적용 범위, 버전 전환 시 상태 보존, 중단·replay 거부, v1 사전점검 거부와 v2 신규 계좌 판정, 사전점검의 파일 불변을 검증한다. 예약 실행 파일은 여전히 v1 설정을 사용한다.

실제 전환은 별도 작업이다. 먼저 새 ID의 운영 장부가 없는지 확인하고, 최신 입력으로 사전점검과 첫 마감 실행을 검토한 뒤 예약의 설정 경로를 전환한다. 기존 장부·미체결 주문은 옮기지 않고 새 계좌는 새 자본 기록으로 시작한다. 과거 날짜를 재실행하거나 누락 봉을 채우지 않는다. 이 준비 PR을 병합하는 것만으로 계좌가 재개되지는 않는다.
