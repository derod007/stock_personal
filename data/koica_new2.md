## 1. Dirty Read = RU

| 문제 | 한 줄 |
|------|--------|
| **Dirty Read** | 아직 **커밋 안 된** 값을 읽음 |
| 어디서? | **Read Uncommitted (RU)** |

```
기억: Dirty → RU
```

| 격리 수준 | Dirty | Non-Rep | Phantom |
|-----------|-------|---------|---------|
| Read Uncommitted | **O** | O | O |
| Read Committed | X | O | O |
| Repeatable Read | X | X | O |
| Serializable | X | X | X |

## 2. 정규화 — 원부이잘

| 단계 | 뭐 하냐 | 암기 |
|------|---------|------|
| **1NF** | **원**자값만 | 원 |
| **2NF** | **부**분 함수 종속 제거 | 부 |
| **3NF** | **이**행 함수 종속 제거 | 이 |
| **BCNF** | 결정자 = 후보키 (**잘** 지키자) | 잘 |

```
원 → 부 → 이 → 잘
1NF → 2NF → 3NF → BCNF
```

## 3. INNER JOIN = 교집합

| JOIN | 결과 |
|------|------|
| **INNER** | 양쪽에 있는 것만 = **교집합** |
| LEFT | 왼쪽 전부 + 매칭 오른쪽 |
| RIGHT | 오른쪽 전부 + 매칭 왼쪽 |
| FULL | 양쪽 전부 |

```
기억: INNER = 교집합
```

## 4. Belady 모순 = FIFO

| 알고리즘 | 규칙 | 비고 |
|----------|------|------|
| **FIFO** | 가장 먼저 들어온 것 교체 | **Belady 모순 가능** |
| LRU | 가장 오래 안 쓴 것 | 실무·시험 단골 |
| OPT | 가장 늦게 쓸 것 | 이론 |

**Belady**: 프레임을 늘렸는데 페이지 폴트가 **오히려 늘어나는** 현상  
→ **FIFO**에서 가능

```
기억: 벨라디 = FIFO
```

## 5. 응집도 = 높을수록 좋음

| | 방향 | 최선 | 최악 |
|--|------|------|------|
| **결합도** | **낮을수록** 좋음 | 자료 | 내용 |
| **응집도** | **높을수록** 좋음 | 기능 | 우연 |

```
응기(응집) = 높을수록
결합 = 낮을수록
```

**응집 순서 (좋음 → 나쁨)**  
기능 → 순차 → 통신 → 절차 → 시간 → 논리 → 우연

**결합 순서 (좋음 → 나쁨)**  
자료 → 스탬프 → 제어 → 외부 → 공통 → 내용

## 6. 배열 vs 연결리스트

| | 배열 | 연결리스트 |
|--|------|------------|
| 저장 | 연속 | 비연속 + 포인터 |
| 접근 | **O(1)** | **O(n)** |
| 중간 삽입/삭제 | **O(n)** (밀기) | 위치 알면 **O(1)** |

```
함정: 배열 중간 삽입은 O(1)이 아님 → O(n)
```

## 7. 정렬 복잡도 · Stable

| 정렬 | 평균 | 최악 | Stable |
|------|------|------|--------|
| Bubble | O(n²) | O(n²) | O |
| Selection | O(n²) | O(n²) | X |
| Insertion | O(n²) | O(n²) | O |
| **Quick** | O(n log n) | **O(n²)** | X |
| **Merge** | O(n log n) | O(n log n) | **O** |
| Heap | O(n log n) | O(n log n) | X |

```
Quick 최악 = n²
Merge = 항상 n log n + Stable
```

## 9. Phantom Read

| 문제 | 한 줄 |
|------|--------|
| Dirty | 미커밋 값 읽음 |
| Non-Repeatable | 같은 **행의 값**이 바뀜 |
| **Phantom** | 다시 읽었더니 **행이 추가/삭제**되어 집합이 바뀜 |

```
팬텀 = 다시 읽었더니 (행이) 바뀜
→ Repeatable Read까지도 가능
```

## 10. 후보키 = 유일 + 최소

| 키 | 의미 |
|----|------|

```
후보키 = 유일 + 최소
```

## 12. Verification vs Validation

본인 암기법 그대로:

| | 단어 길이 | 의미 |
|--|-----------|------|
| **Verification** | **긴 거** | **올바르게** 만들었는가 (명세 부합) |
| **Validation** | **짧은 거** | **올바른 것**을 만들었는가 (사용자 필요) |

```
긴 거 Verifica**tion** = 올바르게
짧은 거 Valida**tion** = 올바른 것을
```

## 13. 테스트 단계

```
Unit → Integration → System → Acceptance
```

| 단계 | 대상 |
|------|------|
| Unit | 함수 · 메서드 · 클래스 |
| Integration | 모듈 연동 |
| System | 시스템 전체 |
| Acceptance | 사용자 최종 (알파/베타) |

**Black** = 기능·입출력 / **White** = 코드 구조

## 14. 유지보수 의미 (CAPP)

| 종류 | 의미 | 한 글자 |
|------|------|---------|
| **C**orrective | 오류 **수정** | 교정 |
| **A**daptive | **환경** 변화 대응 | 적응 |
| **P**erfective | **성능·기능** 개선 | 완숙 |
| **P**reventive | **미래** 오류 예방 | 예방 |

```
CAPP = 교정 · 적응 · 완숙 · 예방
Perfective = 성능·기능 개선 ← 자주 헷갈림
```
