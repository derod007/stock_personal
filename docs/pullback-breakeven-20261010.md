# 종가 +3% 확인 후 다음 세션 체결가 손절 연구

운영은 그대로 고정 손절이다. 이 문서와 CLI는 독립 연구이며 계좌·주문·추천에 연결하지 않는다.

## 고정한 규칙

- 기존 최종 선택 상승 눌림 **전체**를 사용한다. 종료 거래만 미리 선별하지 않는다.
- 기존 실제 모의 체결가 대비 완료봉 종가가 +3% 이상이면 다음 유효 거래 세션부터 손절을 체결가로 한 번 올린다. 체결일 종가도 포함하며 고가만 +3%는 인정하지 않는다.
- 목표·최대 3봉 주문·체결일부터 20봉 보유·비용은 기존 `TradeSimulator`와 같다. 재진입 없음. 임계값 최적화 없음.
- 다음 세션 시가가 목표 이상이면 기존 목표 갭 우선 규칙을 유지한다. 그 외 같은 봉에서 새 손절·목표가 모두 닿으면 손절 우선이다.
- 체결가 아래로 갭이 나면 더 낮은 시가에 슬리피지를 반영한다. 체결가 손절도 수수료·슬리피지 때문에 순수익 0이 아니다.
- 이미 그날 청산된 거래는 종가로 새 손절을 활성화하지 않는다. 잘못된 후속 봉을 건너뛰지 않고 품질 차단하며, 그 이전에 종료된 결과는 유지한다.
- 각 데이터셋 기준일 이후 봉은 사용하지 않는다.

기존 시뮬레이터로 진입·고정 청산을 계산하고, 연구 모듈은 더 이른 체결가 손절의 발생 여부만 덧붙인다. 운영 `TradeSimulator` 및 전략 지문 파일은 변경하지 않았다.

## 최근 기간 실제 결과

2025-10-08~2026-10-08, 최종 선택 82건 전체에서 신호 입력 해시와 기존 결과 모든 필드를 재현했다. 원본 verify 및 dataset/universe/종목별 해시도 검사했다.

- 종가 조건 충족 및 다음 세션 활성 38건, 체결가 손절 청산 21건.
- 공통 종료 70건: 개선 14, 악화 6, 동일 50. 기존 손실이 개선된 14건과 기존 수익이 악화된 5건을 포함한다.
- 기존 미완료 2건 중 1건(로보티즈)이 연구안에서 -0.2497%로 종료됐다. 공통 종료 평균에 섞지 않았다.
- 상태: 기존 종료 70→연구안 종료 71, 미완료 2→1. 미체결 7·진입 전 취소 3은 동일하다.

| 공통 종료 표본 | n | 기존 평균 | 연구안 평균 | 평균 차이 | 기존 평균 R | 연구안 평균 R |
|---|---:|---:|---:|---:|---:|---:|
| 전체 | 70 | +0.8915% | +2.0059% | +1.1144%p | +0.2512 | +0.2845 |
| 전반(2026-04-08 이전 신호) | 48 | +3.5527% | +4.3195% | +0.7668%p | +0.4677 | +0.5319 |
| 후반 | 22 | -4.9149% | -3.0421% | +1.8728%p | -0.2210 | -0.2554 |

R은 순수익률을 원래 체결가 대비 초기 손절 폭으로 나눈다. 손절 이동 후 분모를 0으로 바꾸지 않는다. 후반에는 퍼센트 수익률과 R의 변화 방향이 다르다. 위험 폭이 다른 거래의 개선·악화가 서로 다른 가중으로 반영되므로, 퍼센트 평균만으로 일관된 개선이라고 결론 내리지 않는다.

평균은 개별 거래 평균이며 자금 제약·동시 보유·중복 노출 제한이 없는 연구다. 실제 계좌 수익률이 아니다. 손절을 옮기면 다른 신호를 새로 진입하는 포트폴리오 재구성도 하지 않는다.

## 이전 기간: 실행 대기

사용자 PC에 있는 두 번째 원본과 전체 재현 JSON은 이 환경에 제공되지 않았다. Git의 `pattern-compare-20251002.json`에는 종료 67건만 있어 선택 75건 전체를 평가할 수 없다. 그 67건만으로 대체하지 않았다.

PR 적용 후 아래 명령은 기존 자료를 읽고 결과만 임시 폴더에 저장한다. Windows PowerShell에서 `cmd /c`의 파일 리디렉션을 사용해 PowerShell 버전에 따른 JSON 인코딩 변환을 피한다.

```powershell
cmd /c 'php -d memory_limit=768M bin/paper_breakeven_research.php --dataset-dir="C:\Users\acdun\Desktop\dev\stock-personal-paper\history-research\kr-saved-scan-20251008" --replay="C:\Users\acdun\Desktop\dev\stock-personal-paper\history-research\replay-kr-saved-scan-20251008\pattern-replay-account1.json" > "%TEMP%\pullback-breakeven-prior.json"'
```

예상 `summary.selected`는 75다. CLI는 기존 신호·결과가 하나라도 다르면 중단한다. 이때 검사를 제거하지 말고 오류만 보고한다. 종료 코드를 확인하고 성공한 JSON의 `summary`, `first_half`, `second_half`를 공유하면 된다. 전체 로그/원본 재수집은 필요 없다.

최근 기간 재현에는 Git의 전체 선택 이벤트 요약도 사용할 수 있다.

```powershell
cmd /c 'php -d memory_limit=768M bin/paper_breakeven_research.php --dataset-dir="C:\Users\acdun\Desktop\dev\stock-personal-paper\history-research\kr-saved-scan-20261009" --replay="docs\pattern-replay-20261008.json" > "%TEMP%\pullback-breakeven-recent.json"'
```

커밋된 최근 결과 JSON은 전체 replay를 입력으로 실행했다. Git 요약 입력으로 실행한 82건과 ID별 연구 결과가 모두 동일했다. 입력 파일 SHA256만 다를 수 있다.

## 검증과 다음 판단

신규 13개 검사는 종가/고가 구분, 다음 세션 적용, 갭·목표 동시 도달 순서, 비용, 기존 미완료의 조기 종료, 품질 차단, 실제 체결가 기준, 공통 종료 분모 등을 확인한다. 기존 pattern_replay 17개 검사와 PHP 구문 검사도 통과했다. CI에 새 검사를 추가했다.

다음은 이전 기간 전체를 실행하고 공통 종료의 평균 변화와 R, 손실 감소/수익 기회 감소, 새로 종료된 표본을 함께 비교하는 것이다. 두 기간 결과가 모두 좋아도 이미 탐색에 쓴 기간이므로 운영 채택 근거를 확정하지 않고 새로운 기간에서 검증한다. 2%·5% 등으로 다시 맞추지 않는다.
