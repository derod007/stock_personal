# 기존 감사 로그 일괄 재진단

프로젝트 폴더에서 실행합니다. 새 5거래일을 기다릴 필요가 없습니다.

```sh
php bin/paper_rediagnose.php --account=paper-kr
```

기존 모의 계좌와 같은 `PAPER_STATE_DIR` 환경을 사용해야 합니다. 기본값도 기존 CLI와 같습니다. Windows에서도 프로젝트 폴더의 터미널에서 같은 명령을 실행합니다. 실행 후 탈락 로그 화면의 **기존 감사 로그 일괄 재진단 결과 보기**를 열고 JSON 내려받기를 누르면 전체 결과를 공유할 수 있습니다.

- 모든 `observed_scan_only` 감사 파일을 처리합니다. 재실행 기록도 각각 보존하므로 보고서 건수는 독립 종목·거래일 표본 수가 아닙니다.
- 원본 일봉 SHA256을 먼저 확인하고 당시 시각·저장 프로필·context 옵션으로 현재 엔진을 실행합니다. 현재 fingerprint, 원래 판정, 재계산 결과 및 비교 항목별 차이를 기록합니다.
- **당시 코드 버전을 자동 복구하는 기능은 아닙니다.** `same_compared_fields`도 비교 항목이 같다는 의미일 뿐, 당시 코드 검증을 뜻하지 않습니다. 저장 프로필이 없으면 재계산 오류로 남습니다. 이 경우에만 필요에 따라 `--profile=account1` (`custom`, `isa` 가능)을 지정하면 운영자가 지정했다는 표시와 함께 재계산합니다.
- 거래량 기준 20봉·눌림 3봉의 실제 구간·평균·비율·0 거래량 봉 수, 확인봉 OHLCV, 상승 구조 비교값을 원본 완료봉에서 복원합니다. 복원식은 현재 기준임을 표시합니다. 원래 저장된 통과·실패·미평가 조건은 따로 보존합니다.
- 후속 가격은 같은 원본 해시·종목·파일·판정봉에 연결된 기존 추적 evidence를 우선 사용하며 가격 해시도 검증합니다. 이때 기존 추적 as-of를 넘겨 계산하지 않습니다. 연결된 evidence가 없으면 로컬 `data/ohlcv` 캐시를 사용합니다. 네트워크 조회는 하지 않습니다.
- 다른 로컬 가격으로 비교하려면 `--prices=경로`를 명시합니다. `<symbol>.json` 또는 `<symbol>_2y_1d_closed_v2.json` 형식의 기존 OHLCV 배열 파일을 읽습니다. 지정한 데이터의 출처·해시가 따로 기록됩니다. 과거 기준 실행은 `--as-of=2026-09-30T20:20:00+09:00`처럼 시간대까지 지정합니다.
- 저장된 과거 일봉과 추적 일봉의 OHLCV를 엄격히 비교해 날짜·항목·원본값·추적값·누락을 전부 남깁니다. 불일치 상태에서 봉을 덮어쓰거나 검증을 생략하지 않습니다. 공급자 수정, 원본 병합 차이, 조회 범위 부족 중 어느 원인인지는 상세 결과를 보고 판단해야 합니다.
- 검증을 통과한 경우에만 **기존에 저장된 신호·지정가 후보**로 후속 성과를 다시 계산합니다. 새 코드가 만든 후보로 원래 성과를 대체하지 않습니다. 미래 봉 제한·품질 검사·비용·체결 기준은 기존 추적 로직을 그대로 사용합니다.

결과는 `PAPER_STATE_DIR/rediagnosis/<account>/latest.json`과 실행별 이력에 저장됩니다. `latest`는 마지막 실행 결과이며 과거 as-of 실험을 실행하면 그 실험이 표시됩니다. 기존 `rr-audit`, `followup`, 계좌·주문 파일은 수정하지 않습니다. 오류와 미완료는 0% 수익으로 바꾸지 않습니다. 재진단 실패 기록도 보고서에 남습니다.

우선 이번 보고서에서 13건의 `historical_revision_or_missing` 차이를 확인합니다. 원인 해결 후 적절한 가격 원본을 `--prices`로 지정해 다시 비교할 수 있습니다. 자동 보정이나 운영 조건 완화는 포함하지 않습니다.
