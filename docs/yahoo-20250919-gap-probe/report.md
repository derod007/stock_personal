숫자 근거: `comparison.json`. 새 Yahoo 응답 본문은 Git 밖 `data/raw/research/yahoo-20250919-gap-probe-v1/`(`.gitignore`의 `/data/raw/`). 인증키는 쓰지 않았다.

## Yahoo 짧은 구간과 5년

짧은 구간: `period1=1757894400` (2025-09-15 00:00 UTC) ~ `period2=1758672000` (2025-09-24 00:00 UTC), `interval=1d`. 18·19·22를 포함한다. 같은 시각에 `range=5y&interval=1d`도 따로 받았다. 기존 데이터셋에는 쓰지 않았다.

네 종목 모두:

- 짧은 구간과 새 5년 HTTP 200.
- 2025-09-19 `timestamp=1758240000` (09:00 KST)은 있다.
- 그날 `open/high/low/close/volume/adjclose`는 둘 다 null.
- **5년 응답에서만 null인 것이 아니다.** 짧은 구간도 같은 공백이다.
- 저장 v2 5년 원응답도 같은 시각에 null이다. 정지 두 종목의 v1·v2 SHA256은 같다.

18·22일은 짧은 구간과 새 5년 모두 숫자 OHLCV가 있다.

## 확인한 것

- 2025-09-19는 KRX 원본에 네 종목 모두 정규 OHLCV가 있다. 거래량도 있다.
- Yahoo는 짧은 구간과 5년 모두 그날 시각만 남기고 가격을 주지 않는다. 대표 종목 두 개도 같다.
- 새 조회 URL·시각(KST 2026-10-14 13:38대)·HTTP 200·SHA256은 `comparison.json`과 프로브 `requests.json`에 있다.
- 정지 계좌 `hist-rc-prior-v1-baseline`은 읽기만 했다.

## 미확정

- Yahoo가 시각을 남기고 OHLCV를 null로 두는 이유.
- Yahoo와 KRX가 같은 수정주가 기준인지. 9/22 일치와 9/18 불일치만으로 확정하지 않는다.
- KRX `TDD_*`가 분할·배당 수정 가격인지.
- 이후 Yahoo가 그날 가격을 채울지, 채운 값이 KRX와 같을지.

복구 방식은 이 보고서에서 고르지 않는다.
