# 사전 공시 이벤트와 연구 미체결 주문

가상 데이터로만 개발·검증한 선택형 연구 모듈이다. 공시 원문·실제 종목·실제 계좌 자료를 포함하지 않는다. 데이터 수집이나 운영 연결, 과거 계좌 실행은 하지 않는다.

## 계약

`ResearchEventOrders::apply(state, events, cutoff, sessionOpen)`은 입력 복사본의 새 상태와 취소 로그를 반환한다. `replay`이며 계좌 ID가 `research-event-`로 시작하는 연구 계좌만 허용한다. KRW 당일09:00 시가 전에 호출해야 하며, cutoff는 마지막 처리 세션보다 뒤여야 한다. 휴장일·조기/지연개장 달력은 호출자가 검증해야 하며 이번 버전은09:00 정규 개장만 지원한다.

이벤트 필드: `id`, `symbol`, `kind`, `confirmed`, `published_at`, `available_at`, `effective_open`. 시각은 정확한 Unix 초이며 누락·날짜만 있는 자료는 거절한다. `available_at`은 연구 정책상 사용 가능해진 시각이며, 실제 수신을 가정할 경우 그 근거를 입력 생성자가 보존해야 한다. 발표시각을 무조건 수신시각으로 복사하지 않는다. 발표 이후에만 사용 가능하다.

행사유형은 rights_issue/bonus_issue/split/consolidation을 지원한다. 확정됐고 이번 시가에 발효하며 cutoff까지 이용 가능했던 이벤트만 미체결 주문 취소에 사용한다. cutoff 이후의 정보로 과거 취소를 만들지 않는다. 자동 주문 취소가 거래소 규칙이라는 주장은 아니며, 새 연구 정책이다.

## 장부와 호출 순서

1. 모든 입력을 검증한다. 잘못된 이벤트가 있으면 일부 주문부터 취소하지 않고 예외를 반환한다.
2. 대상 미체결 주문을 제거하고, 그 주문의 예약금 해제액을 기록한다. 이 엔진은 예약금을 실제 현금에서 차감하지 않으므로 **현금을 다시 더하지 않는다**.
3. 변경 전후 예약금 차이와 해제액을 대사한다. 같은 행사가 여러 개면 주문당 한 번만 해제한다. 같은 입력을 재적용해도 이중 취소·이중 반환하지 않는다.
4. 보유 주식은 수정하지 않고 `held_requires_handler`를 반환한다. 하나라도 있으면 `can_advance=false`다. 호출자는 이 경우 엔진 advance를 호출하면 안 된다. 보유기업행사·신주권리 장부는 이번 범위 밖이다.
5. `can_advance=true`일 때 반환된 `state`와 취소 `events`를 함께 보존하고 이후 엔진을 호출한다. 외부 주문 추적 테이블도 취소 로그로 갱신해야 한다. 자동 재주문은 하지 않는다.

기존 운영 코드와 기존 연구 replay 어댑터에 자동 연결하지 않았다. 실제 역사자료를 넣어 사용하려면 별도 이벤트 입력의 커버리지·공시시각 근거를 검증하고 새로운 연구 프로토콜과 계좌를 사용해야 한다. 이 모듈은 모든 기업행사를 처리하는 엔진이 아니다.

## 검증

```sh
php tests/research_event_orders.php
```

가상 검증21개 통과: 사전 정보 취소, 수신 지연, 미래 공시, 다른 세션, 미확정, 정확한 cutoff 경계, 중복/누락 입력 거부, 원본 불변, 현금·예약금 대사, 재적용, 여러 이벤트 한 주문, 보유자 보호, 운영/forward 거부, 실제 PaperPortfolio에서 취소 주문의 비체결 확인.

실제 시장 데이터·공시 전재·기존 연구 계좌 상태나 성과를 포함하지 않는다. 병합/운영 활성화 없음.
