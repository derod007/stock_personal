# 고정 프로토콜: 최근 10봉 저점 손절 대 최근 재하락 고점 이후 저점 손절

이 문서는 대안 손절의 수익률을 계산하기 전에 고정했다. 결과를 본 뒤 기준을 바꾸지 않는다. 고정 시점의 해시는 `freeze.json`에 있다.

## 성격과 한계

- 탐색 연구다. 이 두 기간(2024-10-08~2025-10-02, 2025-10-08~2026-10-08)과 157건은 PR #55~#64에서 이미 여러 번 살펴본 자료이고, 기존 거래 결과도 이미 알고 있다. 완전한 블라인드나 독립 검증이 아니다.
- 운영 전략, 계좌, 원본 데이터, 기존 연구 결과는 바꾸지 않는다. 운영 반영 여부는 이 연구가 판단하지 않는다.
- 저장 스캔에서 사후 고정한 종목군이며 당시 TOP100이나 전체 시장이 아니다. 같은 종목·인접일·겹친 보유는 독립 표본이 아니다.
- 거래별 수익률 평균은 거래 평균이지 계좌 수익률이 아니다.
- 다른 손절 배수, 다른 고점 정의, 필터는 시험하지 않는다.

## 대상

- 기존 상승 눌림(`trend_pullback_v1`)이 최종 선택된 157건: 이전 기간 75건, 최근 기간 82건. 종료 거래만 고르지 않고 미체결·진입 전 취소·대기·미완료를 모두 포함한다.
- 목록은 `population.json`이다. 157건은 `docs/pullback-structure-labels-20261010.json`의 157건과 (데이터셋, 종목, 날짜)로 1:1 대응한다. 신호 가격과 입력 해시는 기존 재현 결과(이전: 로컬 `pattern-replay-account1.json`, 최근: `docs/pattern-replay-20261008.json`)에서 가져왔고 기존 결과는 `baseline-stored.json`에 복사했다. 이 단계에서 다시 계산한 값은 없다.
- 입력 데이터는 `kr-saved-scan-20251008`, `kr-saved-scan-20261009`의 일봉(`bars/`)이다. 해시는 `freeze.json`에 있다. 전략 지문은 `934012285f2ddb3867fff4576dba05fb7df290a36a987c36fc260e8917bbe465`로 두 기존 재현과 현재 main이 같다.

## 그대로 두는 것

신호, 주문가(`entry`), 목표(`target`), 주문 유효 3봉, 보유 20봉, 수수료 10bp·슬리피지 5bp, 체결 규칙(매수 지정가는 지정가 이하에서만 체결, 갭 개선은 슬리피지만큼 줄임), 진입 전 취소 규칙, 갭 체결, 같은 봉에서 손절과 목표가 함께 닿으면 손절 우선(`ambiguous_bar` 표시), 이후 봉의 시가가 목표 이상이면 목표 가격 청산. 손익비로 재선별하지 않고 새 진입·재진입을 만들지 않는다. 손절은 신호일에 고정하고 움직이지 않는다.

**진입 전 취소 규칙은 기존 손절(`plan.stop`)로 판정한다.** 체결 뒤의 손절만 대안 값으로 바뀐다. 같은 일봉에서 체결되고 대안 손절에 닿으면 그 봉에서 청산한다.

## 대안 손절

1. 신호일까지 완료된 일봉만 쓴다(`CandleClock::completed`, 신호 시각 이하). 이후 봉은 어떤 단계에도 넘기지 않는다. 신호일 뒤의 모든 봉을 극단값으로 바꿔도 결과가 같다는 것을 `leak-check.json`으로 확인했다.
2. 큰 조정 시작 고점(H_big): 마지막 120봉(자료가 짧으면 있는 만큼)에서 최고 고가(같으면 가장 이른 날).
3. H_big 뒤 최저점(L_big): H_big 다음 봉부터 신호일까지의 최저 저가(같으면 가장 이른 날).
4. 최근 재하락 시작 고점(H_recent), **PR #64 규칙 그대로**: L_big 다음 봉부터 신호일까지에서, 고가가 H_big보다 낮고 좌우 3봉보다 엄격히 높은 확정 피벗 고점 중 **마지막** 것. 없으면 H_big과 같다. 피벗은 오른쪽에 완료봉이 3개 이상 있어야 확정이다.
5. 대안 손절 = `trunc( H_recent 다음 봉부터 신호일까지의 최저 저가 − 0.2 × ATR14 )`. ATR14는 엔진이 같은 신호일에 계산한 값이고 `trunc`는 `PriceCandidate::trunc`(소수 버림)로 기존 손절(`trunc(최근 10봉 최저 저가 − 0.2 × ATR14)`)과 같다. 기존 손절이 엔진과 이 계산으로 모든 사례에서 똑같이 재현되는지도 확인한다.

### 적용 불가

다음은 모두 "적용 불가"로 기록하고 기존 손절로 대체하지 않는다. 확인 순서는 위에서 아래다.

| 사유 | 조건 |
|---|---|
| `data_insufficient` | 완료봉이 3개 미만이거나 ATR이 없음 |
| `quality_problem` | 창(마지막 120봉의 시간 범위) 안의 원자료 행 중 엔진의 완료봉 필터가 버린 것(무효 OHLC·거래량) 또는 같은 세션의 중복이 있음 |
| `h_big_none_manual_A_only` | 창 최고 고가가 신호일이라 큰 조정 고점이 없음. PR #64는 이 경우 A 수동 표시를 인용했으므로 자동 적용할 수 없음 |
| `h_big_hold_window_edge` | 창이 자료 시작보다 뒤에서 시작하고 창 최고가 창의 첫 5봉 안이라 창 밖이 더 높을 수 있음(보류) |
| `h_big_hold_few_bars_after` | 창 최고 뒤 완료봉이 2개 미만(보류) |
| `h_recent_hold_few_bars_after` | H_recent 뒤 완료봉이 2개 미만(보류). 위 규칙 때문에 실제로는 거의 나오지 않는 방어 조건 |
| `alt_stop_invalid` | 대안 손절이 0 이하이거나 계획 진입가 이상 |
| (체결 뒤) `alt_stop_not_below_fill` | 대안 손절이 **실제 체결가 이상**. 체결을 만들거나 손절을 보정하지 않고 별도 상태로 기록 |

5봉(창 가장자리)과 2봉(고점 뒤 완료봉)과 피벗 3봉은 PR #64에서 이번 연구의 해석으로 고른 값이며 원문 규칙이 아니다.

**해석 결정 하나.** PR #64는 H_big이 보류(창 가장자리)인데도 H_recent를 표시한 사례가 둘 있었다(우리기술, NAVER). H_recent는 H_big 뒤의 구간에서 정해지므로 H_big이 보류이면 H_recent도 믿을 수 없다고 보고 이 연구에서는 H_big 보류를 적용 불가로 처리한다. 이는 규칙을 더 보수적으로 읽은 것이고, PR #64의 24건 중 이 연구 대상인 선택 12건과 나머지 12건 모두에서 상태·날짜가 PR #64와 같음을 `pr64-consistency.json`으로 확인했다(위 두 사례는 PR #64에서 표시, 여기서는 적용 불가로 표기된 의도된 차이).

## 사례별 기록

`alt-stops.json`에 사례마다 H_big, L_big, H_recent(날짜·가격·신호일까지의 완료봉 수), H_recent 뒤 최저점, ATR14, 대안 손절, 기존 손절 대비 변화율, 적용 여부와 사유를 저장했다. 이 파일은 결과를 포함하지 않는다.

## 비교와 지표

- **재현 먼저**: 모든 157건에서 엔진이 다시 만든 신호와 거래가 기존 저장 결과와 같고, 이 연구의 시뮬레이터(손절을 바꾸지 않았을 때)가 기존 `TradeSimulator`와 같다는 것을 확인한다. 하나라도 다르면 대안 비교를 하지 않고 원인을 보고한다(`repro-failure.json`).
- **공통 종료 거래**를 주 비교로 한다: 기존과 대안이 모두 종료(`closed`)한 거래. 한쪽만 종료·미완료인 사례는 따로 표시한다. 미체결·진입 전 취소·적용 불가·미완료는 수익률 0으로 넣지 않는다.
- 기존과 대안의 상태 전이표. 적용 불가와 `alt_stop_not_below_fill`은 별도 열이다.
- 공통 종료 거래의 수익률 평균·중앙값, 개선·악화·동일 건수(순수익률 4자리 비교), 두 방식의 손절 청산 수, 기존 수익 거래(순수익률 > 0)가 대안 손절 청산으로 바뀐 수, 갭 손절과 같은 봉 손절·목표 접촉 수.
- 큰 손실의 기준은 **순수익률 −10% 이하**로 이 시점에 고정했다. 줄거나 늘어난 사례, 변화폭이 가장 큰 5건씩을 보인다.
- 초기 손절 폭: 실제 체결가 기준 `(체결가 − 손절) / 체결가`와 신호 진입가 기준 `(진입가 − 손절) / 진입가`.
- R: ① 두 방식의 수익률을 **기존 초기 위험**으로 나눈 값, ② 각 방식의 **자체 초기 위험**으로 나눈 값. 위험은 체결가 기준이다.
- 같은 비교를 손절 수준이 실제로 다른 거래로 줄인 값도 함께 적는다. 수준이 같으면 거래가 같을 수밖에 없기 때문이다.

## 순서

1. `population` → 2. `alt-stops` → 3. `pr64-check`, `leak-check` → 4. 이 문서와 코드 확정 → 5. `seal`(해시 고정) → 6. `run`(고정 확인, 기준 재현, 대안 적용).

6단계 이전에는 대안 손절이 적용된 거래 결과를 계산하지 않았다. 단위 테스트는 합성 데이터만 썼다.
